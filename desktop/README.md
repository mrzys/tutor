# 智教桌面版

SolidJS + Tauri 2 + Rust，首个交付目标为 Windows。首次使用只设置昵称，
无登录、注册、邮箱、管理员或远程个人数据服务。
仓库只维护桌面应用；token、来源显示与富文本解析均在 `desktop/src/`，不再引用旧网页或 Node 服务。

0.1.34 内置 378 道已入库题目：原种子 358 道保留不变，另以 `bank-supplement-v1.json`
追加本机已发布的 20 道题与 6 个图片素材，原始发布凭据和映射一并保留。
补充包在标注升级后事务应用，重复启动幂等；本地冲突回滚并显示提示，不覆盖已有数据。
本次按用户明确要求使用 `npm --prefix desktop run tauri -- build --bundles nsis` 生成安装包，
常规 `npm run desktop:build` 仍只生成 EXE。

开发调试／维护二进制需显式启用 Cargo 的 `dev-tools` feature，例如
`cargo build --manifest-path desktop/src-tauri/Cargo.toml --no-default-features --features dev-tools --bin tutor-desktop-driver`。
默认桌面构建及安装包不启用该 feature，只分发正式主程序。

本地 macOS 包可在 Mac 上执行
`APPLE_SIGNING_IDENTITY=- npm --prefix desktop run tauri -- build --bundles app,dmg --ci`。
`tauri.macos.conf.json` 仅为 macOS 选择 `.app`／DMG 与已有应用图标，不改变 Windows 的 NSIS 配置。
产物位于 `src-tauri/target/release/bundle/`；按本机构架编译，临时签名且未经 Apple 公证。
0.1.35 已支持 macOS 钥匙串保护模型／OCR 密钥；PDF 导出及 DOCX 转换仍只有 Windows 实现，不因打包成功冒称已适配。
release 启动会使用系统应用数据目录，不接受调试数据目录变量；未隔离时不自动进行个人数据烟测。

## 开发与构建

需要 Node.js 24、Rust 1.90+、Windows C++ 构建工具及 WebView2。
在仓库根目录执行：

```powershell
npm ci --prefix desktop
npm run dev
```

Vite 开发端口为 `1420`，由 Tauri 自动启动；日常用户直接打开桌面程序，
不需要浏览器地址、Node 服务或 Python。

```powershell
npm run build
npm test
npm run desktop:build
```

`build` 检查 SolidJS 类型、前端构建与 Rust；`test` 先验证题位任务与目标关联，再运行使用隔离临时数据目录的 Rust 回归。
`npm --prefix desktop run test:blueprint` 可单独运行全部 `desktop/tests/*.test.mjs` 前端回归（目标关联、富文本、表格、图片及版本隔离）。`npm run test:tools` 验证独立离线迁移工具。模型失败恢复测试使用本机模拟 HTTP 服务，不调用外部模型，也不读取实际用户数据库。
`desktop:build` 仅生成 Windows 可执行文件，跳过安装包制作。运行
`desktop/src-tauri/target/release/tutor-desktop.exe` 即可启动；现有本机数据继续保存在应用数据目录。
`npm --prefix desktop run desktop:build -- --debug` 可构建调试可执行文件。
构建产物位于 `desktop/src-tauri/target/`，不提交 Git。
后续默认只交付 EXE，用户明确要求时才制作安装包；已有安装包保留。

## 开发者组卷日志

日志区分别显示请求、模型调用及阶段耗时；模型时间包含在相应阶段内，不应相加。新记录用单调时钟测量，旧记录可配对时按事件时间戳推算并标识；失败和取消会保留未完成阶段的实际终止状态。界面的最短视觉停留不属于后端执行耗时。

正式 EXE 默认隐藏日志入口。在“设置 → 本地数据 → 开发者模式”显式开启后，右下角显示日志入口；本机选择会保留，下次启动继续生效。关闭立即停止正文采集并禁止读取，已有日志保留。也可在排查时显式启动：

```powershell
& .\desktop\src-tauri\target\release\tutor-desktop.exe --developer
```

也可在启动该进程前设置 `TUTOR_DEVELOPER_MODE=1`；`TUTOR_DEVELOPER_MODE=0` 优先关闭，包括调试构建。调试构建未显式关闭时默认开启。
开启后，组卷页面右下角的“开发日志”以非模态悬浮窗口打开，不锁定工作区。窗口支持收起、放大和独立滚动，按流程、状态与阶段查看，并支持暂停刷新、查看历史及复制。

组卷请求沿用同一流程标识，记录需求整理、题位规划、选题、草稿修改、预览、确认成卷和 PDF 输出的真实结果、耗时、失败及取消。模型事件保存实际发送的 system/user 消息、请求参数、原始服务响应、解析结果和业务校验；输入输出正文按事件点开后读取，不用界面提示语替代实际数据。
密钥、认证头与学生关联字段在写入前移除，题目正文、教师要求及参考解析保留用于开发排查。正文只在显式开发者模式下追加，普通运行仅记录白名单统计信息。

日志存放于本机应用数据目录的 `diagnostics/assembly-log.sqlite`，独立于个人库和题库；读取不占组卷锁，不发起模型请求或改变业务数据。保留最多 40 个流程、每流程 500 条、合计 5000 条事件；单项正文最多 4 MiB、单流程正文 32 MiB、全部正文 128 MiB。超限截断或明细过期会明确显示，已有普通运行日志不会补造未采集的正文。

## 使用与模型

首次输入昵称即可使用。组卷仍按需求确认、题位规划确认、真实选题、编辑草稿、
确认成卷进行；规则预设由教师显式选择，不会把规则结果冒充 AI 结果。题量不足
保留空位并说明原因。学生关联只用于本机归档，不印入试卷或发送给模型。

编辑页不再常驻显示“需求 / 题位规划 / 试卷”进度导航。题型 Tab、总题量与当前题型的全选同行，
桌面将预览、添加题目及确认成卷放在题目右侧；“组卷说明”从右侧抽屉查看需求和当前题位的题型、考查点，点击外部或按 Escape 关闭。
切换题型预留相同滚动条空间，题目宽度保持稳定；窄屏将右侧操作收回题目上方。
添加题位默认跟随当前题型，可重新选择；考查点只提供匹配题型的选项。带 Tab、搜索或切换功能的模态框保持固定外框高度，长内容在内部滚动。

新建组卷的考查范围按本地真实教材 → 章 → 小节展示，保留已有选择；父级支持全选和半选。搜索保留祖先层级，搜索时章节批量勾选仅作用于匹配小节。没有组卷任务的小节仍展示但暂不可选，目录读取失败可重试。弹窗只在列表内部滚动。

规划中修改考查任务时保留仍兼容的教学目标关联，并移除该题位的旧规划理由与过期供给结果。必须目标失去全部兼容题位时，展开目标面板并阻止开始选题；教师可通过“关联题位”显式重绑，不自动降低目标优先级。重绑不会把目标关联当作已证实覆盖的证据；取消不修改规划，重新确认仍经过 Rust 校验。

题位 AI 规划仅发送已确认范围内、所需题型的任务目录，保留无供给任务以如实展示缺口；审核台账、来源详情及重复的题号、分值不进入规划请求。模型返回任务身份、目标关联及可选的简短理由，程序补齐题型、连续题号与分值，再校验题量、范围和必须目标。输出预算按题位数分配（60 题为 10624 token）；官方 HTTPS DeepSeek 的 `deepseek-flash`／`deepseek-v4-pro` 规划请求明确关闭思考、最低预算 4096，其它服务和模型保留至少 8192，不猜测专有参数。失败不自动换模型或改用规则，不接受截断结果；需求保留，可显式重试或选择“使用规则预设”。

最近一次模型规划的诊断写入应用数据目录 `diagnostics/blueprint-last.json`，仅记录请求字节数、任务／教材小节数、确认题量／参考题位数、预算、模型阶段耗时、token 用量和结束原因；不保存教师正文、题目、响应正文、服务地址或密钥。后一次请求覆盖前一次，缺失的服务端用量保持未知；诊断写入失败不影响规划结果。此耗时不包含本地题库准备与最终供给校验，不能据此声称整个流程已提速多少。

可在设置中保存多套模型配置，支持 DeepSeek、阿里云百炼、小米 MiMo 和独立的千问AI平台。先选择服务商、填写该配置自己的 API Key，再点击“获取模型列表”，由 Rust 调用对应服务商的 `/models` 接口；可搜索返回的真实模型 ID。接口失败显示原因并允许重试，不用静态候选兜底。读取设置或历史不自动联网，拉取不修改当前启用配置、不占组卷锁。完成编辑后仍需显式保存。

`resources/llm-providers.json` 固定服务商地址并保存确切已知模型的能力信息，不是可用模型目录。千问AI平台固定为 `https://maas.qianwenaiapi.com/compatible-mode/v1`，与百炼的来源身份和密钥分开。百炼使用北京按量付费接口，小米使用其 OpenAI 兼容接口；已有明确思考设置随配置保存，旧配置缺项不自动开启。动态未知模型不按名字继承其它服务商参数，也不把列表返回等同于已验证支持对话或结构化输出。MiMo 已知模型使用 `max_completion_tokens`。

千问AI平台仅对已验证的 `qwen3.8-flash` 提供关闭／开启思考，通过顶层 `enable_thinking` 发送布尔值，不虚构强度档位；能力元数据不作为 `/models` 失败后的模型列表兜底，原配置未显式设置思考时继续沿用原请求策略。

新动态模型保存须匹配实际列表的服务商、配置身份、凭据和模型；目录授权仅在本机进程内短期保存，不写入配置文件。切换服务商或密钥清除编辑器旧列表并拒绝迟到响应。旧配置保留原名称、地址和模型别名，未变化项可离线保留；其它服务商的旧配置可查看、保留或删除，不新增自定义地址。用户本次提供的 `~/.agent.env` 仅供离线维护验证，正式应用不自动读取其中密钥。

接口依据：[百炼 Base URL](https://help.aliyun.com/zh/model-studio/base-url)、[百炼 Chat Completions](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)、[MiMo API 接入](https://mimo.mi.com/docs/en-US/quick-start/faq/api-integration)、[MiMo 结构化输出](https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/text-generation/structured-output)。
设置为独立页面：左上返回组卷，左侧切换个人设置、模型配置、试卷识别与本地数据，右侧编辑具体内容。
个人与模型设置分别保存，切换设置项保留未保存输入；返回前提示未保存修改，原组卷工作区保留。
新增、编辑、删除与切换在点击“保存”后生效；取消不会修改配置。切换配置本身不请求模型，后续 AI 操作使用当前项。
原有单套配置保留并自动识别，首次显式保存时升级文件结构。密钥不回显；编辑时留空只保留该项原密钥，新增配置不复用其他密钥。Windows 使用 DPAPI；macOS 将随机主密钥保存在系统钥匙串，配置文件仅保存 AES-256-GCM 认证密文。钥匙串拒绝访问、密文损坏或主密钥丢失均提示重新设置，不明文回退。
切换服务地址的来源时需重新输入密钥。不配置当前模型仍可显式用规则预设；导入试卷需要当前配置完整。
开发调试可沿用根 `.env` 的模型配置；正式发布版本不读取或捆绑开发密钥。
模型建议仍需教师确认，读取历史与预览不请求模型。

### 学生答卷

左侧“学生管理”维护姓名／昵称、年级和本机备注。选择学生后上传答卷，可关联本机已确认成卷，
或填写外部练习名称并上传答卷，原试卷可选填；不要求额外勾选完整题目声明。模型按实际材料识别题干与作答，缺少必要题干或依据的题保留暂无法判断；原卷缺失不阻止保存和发起批改。
支持 PDF、PNG、JPEG，每个文件不超过 15 MB，原题与答卷合计最多 8 份、45 MB。
作答日期未知时可留空，上传时间单独保存。

“仅保存”不需要模型配置、不会调用外部服务。“保存并批改”先保存原件，再使用当前配置的
PaddleOCR 和模型后台处理；可以离开学生页面继续组卷。材料会发送到配置的服务，图像自身
可能包含姓名；应用不主动附加学生资料和自由备注。中断、取消、失败后保留原件，重试需显式发起。

结果区分未作答与暂无法判断，不把辨认不清当成错误。无真实赋分上限时不虚构分数，第一版不自动汇总总分。
可以按需修正判断、得分和评语，AI 原始结果与教师修正分别保留，不要求逐题确认。
本机成卷快照随答卷保存，隐藏原成卷不改变答卷原题。读取历史、原件及结果不调用模型。
批改记录不自动生成掌握度、学习计划或改写组卷条件；模型数学评分与手写识别质量需要真实样本验证。

### 上传试卷与 PaddleOCR

在“设置 → 试卷识别”填写 PaddleOCR API Key，接口默认为
`https://paddleocr.aistudio-app.com/api/v2/ocr/jobs`，识别模型默认为 `PaddleOCR-VL-1.6`。
这是独立的识别配置，不能使用模型配置中的密钥代替；留空保留原密钥，清除需勾选后保存。
修改配置仅在保存后生效，密钥不回显；并发修改会提示重新读取，不覆盖另一窗口的保存。

“导入试卷”选择 PDF／DOCX 前同时检查当前模型与识别配置；Rust 在解码、读取及保存上传文件前再次检查。
PDF 发给 PaddleOCR；DOCX 先由本机已安装且可正常自动化的 Word 或 LibreOffice 转为 PDF，再识别。
未安装转换工具时提示先自行导出 PDF，不使用纯文本提取掩盖公式或图片丢失。
每次支持 1–50 页、原文件不超过 15 MB。开始解析会将试卷内容发送至配置的识别服务，
识别文字、布局及素材引用再交给当前 LLM 拆题与标注，不向 LLM 发送 OCR 密钥。
“导入文本”仍支持 UTF-8 TXT／Markdown，仅需模型配置。

原件、逐页 Markdown、原始版面块、原页图片、实际图表裁图、识别审计与模型尝试保存在本机导入目录。
当前官方 `deepseek-flash` 导入会同时接收已保存的实际题图和图表裁图，以辅助核对跨页归属；
OCR 文字与版面仍完整提供，整页图片不冒充题图。其它模型保留文本方式，不静默切换服务。
未知阅读顺序保留为空，不强行按 0 排序；页数矛盾、缺图或未完整分配图表会阻止相关发布。
题号核验兼容 `1.`、`（1）` 与 `(1)`，仍拒绝缺题、重复及多出的题号。
跨页配图列入显式素材清单；严格匹配的三行空白卷面记分栏保留在原件中，
不当作题目表格。已填分数、公式表、数据表和结构异常表格不适用此例外。
表格逐行逐格核对结构，保留空单元格和合并单元格；不会用 LLM 生成的示意图代替原图。
审核和发布均检查不可变的表格结构基线，误删表格或行列时阻止确认；教师仍可更正 OCR 文字和单元格数值。
识别成功而模型整理失败时，显式重试复用已校验的识别材料，避免重复 OCR 调用。
模型返回非法 JSON 或未完整归属原卷图表时，仅从同一原文自动重新整理一次（两类共用一次额度），
分别保存每次请求摘要、原始响应与内容校验结果；不修补坏 JSON、不猜测挂图，也不重复识别。
再次失败提示具体原因并保留原件；
截断、内容或标注校验失败不自动放宽条件，仍须显式处理。
打开导入历史、查看及审核不会调用识别或模型；模型结果仍全部待审核，教师核对并确认后才入库。
失败详情明确显示阶段、具体原因、可定位的题号／页码或模型格式位置，以及下一步。
旧泛化错误可只读分析哈希校验通过的原始响应；没有足够记录时如实保留未知原因，
不通过重新调用服务猜测。诊断不会改写历史记录或原始响应。
导入后的图片随题目冻结保存，源材料与图片哈希校验失败时不能通过勾选确认忽略。

导入记录直接显示为分页列表，每页 10 份，展示名称、状态、题数和导入时间。

AI 整理需求时由 LLM 从原话提取允许／排除题型、明确数量和总题量，并结合教学用途、时长、考查范围、教学重点及真实题库供给提出完整题型配比与简短理由。程序校验总量和硬约束，保留教师已经手动确认的设置；未指定的配比不再按默认权重补齐。只有已确认全部数量或硬约束唯一确定配比时可省略建议，缺失或无效的模型建议明确失败，不静默回退正则。题型供给按真实版本、范围、已学边界及重复组核对，只是后续具体任务选题的参考上限；不足保留缺口，不放宽条件。AI 建议与教师明确数量分别保存，确认需求前直接显示实际题型数量与“AI 配比建议”理由；手动改变数量后清除旧理由。泛称“选择题”包括单选和多选，建议的细分不冒称教师指定。规则预设保留本地解析，支持“只要选择和填空题”等组合。原话不变的再次整理保留手动确认值，修改原话则作为新需求重新理解，未重新指定的规模可沿用，不以旧确认锁死本次明确修改。

切换考查范围后不沿用其它章节的默认教学说明或旧目标；没有明确教学重点时按当前真实章节生成中性说明，不推断学生掌握情况。已有成卷快照保持原样。

“组卷说明”的逐题安排显示难度：选题要求采用基础、基础偏中等、中等、中等偏较难、较难五档，可在“调整题目”中与考查点一并确认保存；修改要求不自动换题。旧数值目标显示“旧版目标”并保留原值，不猜测为某个分档；早期 0～1 参数越大越偏基础，未经学生作答标定，不代表正确率。题目分档读取草稿冻结、版本一致的题库内容估计，缺少依据显示未评估；不会把已有三档数据自动细分，也不将内容估计当作学生作答标定。

学生卷的整卷预览及新生成 PDF 隐藏来源和难度；教师卷显示简短来源及每题的冻结难度内容估计（未标注显示“未评估”），不使用本次目标难度替代。已有 PDF 保留，需显式重新生成才能应用新排版；草稿编辑及题库仍显示来源。

五档具体标准见 [数学题难度口径](../docs/design/difficulty-rubric.md)，选择难度时可查看当前档说明及折叠对照。界面、模型规划、导入和显式重标共用 `resources/difficulty-rubric.json`；不按知识点数量或计算步数机械划档，不自动重标旧题，不预测正确率。

设置 → 本地数据 →“重新标注题库”可按教材显式重评现有可用题，选择完整重标（难度、主考知识点、逐解法依赖）或仅难度。先查看范围，再开始模型调用；不包含待审核题。成功结果逐题事务保存，失败保留原标注，支持暂停、恢复、只重试失败题。历史记录保存原标注、原始模型响应、模型身份与标准版本；并发和版本冲突不会覆盖已有修改。模型配置改变后不静默换模型继续。

重标只更新版本绑定的题库索引，不修改题面、来源、数学审核状态或已有草稿／成卷；重新读取、查看任务和预览不调用模型。题目详情可查看难度依据和各解法依据。标注结果属于模型内容判断，不代表重新验算或教学效果验证。

编辑草稿的每道题提供“详情”入口，沿用悬浮操作区，不增加题目留白；键盘聚焦和触控时同样可用。右侧只读抽屉显示题目难度、实际考查点、知识点、小节及完整来源，并单列本题位的考查点和难度要求。逐解法知识依赖按需展开，不合并不同解法，也不把旧泛化相关知识冒充新版主考 UID 标注。查看详情不请求模型、检索新版本或保存草稿；版本不一致及未标注信息如实留空说明。

Windows PDF 采用 WebView2 原生 A4 排版，学生／教师内容分别渲染；生成成功后
才写入选定文件，归档副本保留。macOS 密钥已通过独立测试服务的真实保存、重开和替换校验；macOS PDF 与 DOCX 转换仍待适配，Linux 密钥存储未实现。

## 标注结果分发

`desktop/resources/bank-annotations-v1.json` 是独立于原始迁移台账的元数据升级包，只更新难度、主考知识点和解法依赖。新库和原始旧库按内容、版本及旧标注哈希进行事务升级；已有本地标注冲突时整体回滚并提示，不覆盖教师修改。原始来源、数学审核证据、题面、个人记录及冻结成卷保留。

开发维护可用 `scripts/export-desktop-annotations.mjs` 从已完成的本机重标导出升级包，必须提供重标前任务报告作为旧标注基线；导出仅读取共享题库和索引，不读取个人记录、模型密钥或原始模型日志。导出后需运行真实打包升级回归，不能仅因模型返回成功就声称整册覆盖或数学正确性已验收。

2026-10-20 实际执行：358 道可用题全部完成难度、主考知识点及逐解法依赖重标，五档分别为 77／146／105／29／1。357 题保存有依据的完整路径；1 题原解析缺少排序归约论证，路径留空、自动适配未知，未补编原解析。题面、教师答案解析及个人文档哈希与重标前一致，14 条待审核台账未被提升为可用。结果是模型内容标注，开发抽查不代表全库数学审定。

## 导入审核阅读工作区

审核详情统一显示排版后的题干、选项与原卷实际答案解析，复用安全富文本和 KaTeX 渲染器，不区分学生版和教师版；点击“编辑内容”可修改原始文本及标注，“查看排版”返回阅读，修改仍需显式保存。旧库参考单独标明，原卷缺失的答案解析保持空缺。其它预览及 PDF 的学生／教师版本边界不变。

题目导航显示题号、题型及处理状态；考查信息展示实际保存的五档难度、考查点和知识点，难度依据和逐解法依赖可展开阅读。导入模型在整理题目的同一次响应中返回检查意见与自评置信，不设独立初审步骤，不在解析后逐题额外请求。高置信且通过完整性校验的题可统一确认入库；疑点重点处理，人工核对清单折叠保留。检查失败、缺少意见或修改题面后可按需“重新检查”。读取历史不外呼，内容损坏、缺图和选项不完整仍由 Rust 阻断，模型意见不等同独立核验。保存修改与加入题库仍为独立操作。


## 后台导入与按内容核对

选择文件后原件先保存本机，OCR 与 LLM 在独立后台连接中运行，最多同时处理两份，后续排队；可以离开导入页继续组卷、浏览题库或管理学生。导入记录与侧栏标记显示进展，完成或失败给出通知。停止仅取消指定导入任务；退出应用后已保存材料保留，中断任务需显式重试，不在重启时自动调用服务。

“加入题库”位于审核详情右上方，审核保存仍独立。题干与公式图表保真检查保留，原卷实际有答案或解析（含小问）时才出现对应核对项；缺项保持空白，旧库参考不算原卷答案。原图／原文对照支持真实 Paddle 整页图、识别后原文、并排查看与缩放；旧记录可用保留的原卷 PDF 对应页回退，不重新 OCR。

难度内容估计、主考知识点和完整解法依赖分别处理。原卷无答案解析时，足够明确的题面仍可估难度和主考点；不足的维度保持未知，不生成解析凑齐标签。教师可显式点击“补充考查信息”，后台只补未完整的元数据，保留题面、答案解析、素材、已发布题及已有审核。没有可靠完整解法的题仍可审核入库并手动组卷，自动选题继续保留已学边界检查。既有记录不会因打开页面自动重新标注。

组卷使用指南为离线模拟动画：逐字输入、需求整理、题位出现、选题进度、换题与整卷预览；默认静态，支持播放、暂停、重播及减少动态效果，不调用模型或改变业务数据。

2026-10-22 显式题库维护：难度依据与 AI 教学解析可按已确认提示词重新整理。教学解析以独立版本绑定原题面及教师版，模型来源和待复核疑点可见；题目信息及教师卷优先显示新教学稿，原解析保留对照。学生卷不展示解析，已有草稿／成卷及原 PDF 不刷新。维护命令 `tutor-bank-maintenance teaching-apply --data-dir <本机目录> --manifest <结果清单> --report <回执>` 只打开现有题库，按题目和旧标注哈希原子写入、幂等重试并保存旧稿审计，不打开个人库、不执行内置题库迁移、不修改原题及原审核。
