# 智教

面向私教的本地桌面应用，使用 **SolidJS + TypeScript + Tauri 2 + Rust + SQLite**。
当前只有桌面端，不提供网页服务、登录、注册或账号管理；首次使用设置本地昵称即可。

## 功能

- 组卷：需求确认 → 题位规划确认 → 真实题库选题 → 编辑草稿 → 确认成卷，缺题保留并说明。
- 题库：教材与知识点导航、筛选、手动组卷篮，以及 PDF／DOCX／文本导入和审核。
- 预览：完整学生卷／教师卷、公式、图片和表格渲染，使用 Windows WebView2 输出 PDF。
- 学生：基础资料、答卷原件、后台 AI 批改与历史记录，教师可按需修正，不自动推断掌握度。
- 设置：多套本机模型配置与独立 PaddleOCR 配置，密钥由 Windows DPAPI 或 macOS 钥匙串保护。

模型配置页分为“用途分配”和“模型与密钥”。普通导入只选择“处理模型”（DS Flash）和“复核模型”（阿里云百炼 Qwen），分别保存模型与思考设置。显式选择处理模型会同时绑定拆题与内容生成，旧拆题思考设置按适用情况保留；旧用途位于默认折叠的高级设置中。组卷等任务继续使用通用配置。读取不迁移配置、不外呼；已有任务沿冻结原策略。具体约定见[导入教学稿流程](docs/design/import-teaching-workflow.md)。

2026-11-02 已采纳[导入准确性优先设计](docs/adr/0010-import-accuracy-first.md)，2026-11-03 按用户要求采纳[两模型合并流程](docs/adr/0011-two-model-import.md)：OCR 输出和最终题目内容/教学信息合同保持稳定，中间策略独立版本化。新上传在来源转录后，每题一次生成解答与教学候选，再一次对照真实材料统一核对来源、数学及教学信息；取消额外盲解，不把模型同意当作独立真值。正常后处理由六次降为两次，OCR、索引、转录和显式修订另外计算。过程证据、预算和版本独立保存，发布重放不外呼。旧六步策略完成过隔离工程及单卷真实服务[试导入检查](docs/validation/import-accuracy-first-real-paper-2026-11-02.md)：21 题中 2 题可确认、19 题待处理，未强制入库；该结果不是新两段策略的准确率证据。真实模型准确率与 40 题独立复审试点尚未完成。

PDF／DOCX来源整理采用整卷索引与3个常驻worker分批转录，来源阶段每次操作共用120秒截止；OCR和教学稿不计入该阶段。复用已保存OCR，保留跨页题及原卷答案对应，成功批次不重复生成，显式继续只处理未完成部分；整卷完整性通过后才进入审核和教学稿处理。

模型执行直接使用已保存的服务商、型号、凭据与思考设置，不在拆题、生成或复核前请求模型列表。设置页的“获取模型列表”仍由用户主动发起；执行接口报告型号不可用或其他错误时保留已有成果，不自动换模型或追加重试。

OCR任务已受理但下载材料失败时，显式继续通过原任务恢复下载，校验并复用已保存图片，不再次提交识别。旧记录缺少原件绑定时需先核对旧任务证据。表头识别错误和扫描页脚素材可以按原图保存精确的来源核对凭据；原OCR、原始模型响应与成功断点保持不变，有歧义的条件、题号或素材继续待处理。

处理进度分别显示当前阶段与具体错误：网络／配置／基础服务、模型输出或内容、业务与原卷材料分别说明，证据不足保留原因待定位。错误详情展示原始代码，普通界面提供中文原因、断点与下一步，不因分类而自动重试或放行，见[阶段与错误展示](docs/design/import-processing-diagnostics.md)。

解析复核的新请求按确切句段授权修改；需要换方法时，只允许改写与原题小问明确对应的完整证明段，其余文字保持原样。模型仅返回短请求号、句段号和改写文本，版本与原文哈希由本机验证；声称已修复须实际改动该疑点所在获准范围。失败保留初稿与原因，继续待复核，不自动回退放行。旧补丁审计保持原义，程序合并通过仍不代表数学正确。

0.1.35 安装包内置 378 道已入库题目：原始种子 358 道及已发布补充题 20 道（含 6 个图片素材）。
首次启动离线初始化题库；升级通过事务增量补充，保留个人记录、本地修改与旧来源台账。

外部练习可仅填写名称并上传答卷，原试卷选填；缺少必要题干或依据时保留“暂无法判断”。
模型请求只在用户明确发起时执行，阅读历史不外呼。模型估计与工程回归不代表真实教学效果。

## 开发与验证

Windows 需要 Node.js 24+、Rust 1.90+、C++ 构建工具及 WebView2。
在仓库根目录执行：

```powershell
npm ci
npm run desktop:install
npm run dev
```

Tauri 自动启动 `1420` 端口的 Vite 开发服务；正式 EXE 不启动 Node 或本地 HTTP API。

```powershell
npm run build
npm test
npm run test:tools
npm run desktop:build
```

- `build`：Solid 类型检查、界面生产构建及 Rust 检查。
- `test`：桌面前端规则／渲染数据回归与隔离 Rust 测试；独立Rust用例最多4个并行，避免Windows高核数下数百个SQLite／HTTP模拟同时争用资源。每个用例内的来源worker、后台任务、取消及并发断点测试仍执行实际并发。
- `test:tools`：离线题库迁移和整卷来源转换回归，不使用真实个人数据。
- `desktop:build`：仅生成 `desktop/src-tauri/target/release/tutor-desktop.exe`，不制作安装包。

开发版可使用根 `.env` 的模型配置，示例见 [.env.example](.env.example)。正式版只使用本机设置，
不读取或打包开发密钥。普通 PDF／DOCX 试卷导入前须配置模型和独立 PaddleOCR；DOCX 转换需要
已安装 Word／LibreOffice，否则先导出 PDF。桌面运行与 PDF 输出不依赖 Python。

## 本机数据

Windows 默认保存在 `%APPDATA%/fun.mrzys.tutor/`。个人记录使用 `personal.sqlite`，
共享题库使用 `question-bank.sqlite`；导入原件、答卷及输出附件分别归档。关闭应用后备份整个目录。
用户已选择从空白个人数据开始，旧 `.tutor/` 和网页个人数据库保持原样，禁止自动合并或清空。

## 仓库结构

| 路径 | 用途 |
| --- | --- |
| `desktop/src/` | SolidJS 界面、共享 token、来源显示和富文本渲染 |
| `desktop/src-tauri/` | Rust、Tauri、存储和模型调用 |
| `desktop/resources/` | 版本化题库种子、标注和难度口径 |
| `desktop/tests/` | 桌面前端回归 |
| `scripts/` | 构建入口和显式离线迁移／资料准备工具 |
| `data/`、`materials/` | 来源台账、教材与研究资料，非运行数据库 |
| `docs/` | 产品决策、设计和验证记录 |

旧网页、Node 服务、网页测试及部署配置已退休，共享代码已迁入桌面目录；历史实现可从 Git 追溯。
旧验证记录保留其发生时的路径和命令，不作为当前运行方式。
