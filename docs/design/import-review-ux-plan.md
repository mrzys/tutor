# 导入审核 UI / UX 改造方案

- 日期：2026-11-02。
- 状态：A—D 已实施并完成隔离回归；本页末尾记录验证范围与限制，不代表真实教师使用验收。
- 范围：导入记录、原卷对照、单题核对、字段编辑、考查信息入口和入库确认。
- 依据：用户提供的 Gemini review、本轮实际界面复查、现有代码及[导入教学稿流程](import-teaching-workflow.md)。
- 目标：操作直观、正文与当前问题优先、低频信息按需出现。沿用现有 token、Lucide 与共享弹窗组件。

## 1. 设计取舍

采用“单题阅读、问题就地处理、整卷统一入库”的呈现方式。原题、AI教学稿和考查信息在同一阅读区域内有明确来源标签；后台的保存、核对与发布边界继续独立。

| Gemini 建议 | 本方案处理 |
| --- | --- |
| 收敛原卷查看入口 | 采纳。保留一个原卷查看区域，放大、整份PDF和识别原文从该区域进入，复用已有读取与校验能力。 |
| 自动显示原卷切片 | 调整。只有可靠的持久化坐标和素材绑定才能定位；缺少依据时显示整页，不按题号或比例猜切片。跨页题仍能查看全部相关页。 |
| 题面 → 答案解析 → 考查信息 | 采纳阅读顺序，采用按需展开的内容段，避免全部展开成长表单；当前疑点对应内容自动展开并定位。 |
| 取消原题／AI双领域切换 | 删除右栏重复Tab，用一份具体问题清单和来源标签承载；原题确认、AI稿保存及采用仍分别表达。 |
| 单一“通过并看下题” | 调整。保留明确的“确认原题并继续”，不暗示同时确认AI稿或完成入库；下一题按当前任务选择。 |
| 顶栏精简、移除四色进度 | 采纳。先修正计数，再保留一个原题资格概览；原题与AI待办使用各自口径。 |
| 点击字段轻量修改 | 采纳。使用明确的铅笔入口或字段点击打开定向编辑，复用原文编辑与预览，不直接编辑KaTeX生成的DOM。 |
| 失焦自动保存 | 不采用。保留本窗口草稿和显式保存；失焦、切换阅读区域、查看原卷都不提交业务修改。 |
| 技术信息全部放开发者日志 | 调整。哈希、内部代码、请求明细留在诊断；普通用户仍能查看具体失败、核对依据、已用复核额度与本次入库范围。 |
| 普通Enter确认 | 不采用。保留按钮和Ctrl+Enter，输入框、输入法组合输入和弹窗内不触发后台确认。 |

“90%的修改只是改一个字”尚无真实使用数据支持。字段编辑优先属于本轮待验证的设计假设。

## 2. 先统一状态口径

### 原题资格与AI状态分开

本轮隔离模拟卷复现：原题实际可入库10题，其中8题可同时包含AI教学稿、2题仅原题；现有进度却显示17题已就绪、89%。原因是进度将 `publicationScope=source_and_teaching` 当作资格，漏查 `eligible`，计入了7道原题尚未通过的题。

- 原题可入库数量与确认清单都使用Rust实际 `eligible`；不从AI稿是否存在、范围字段、颜色或本地编辑状态推断资格。
- 原题导航状态按已入库、重复、未采用、可入库、待核对分别归类，按固定优先级互斥统计；待核对内部保留缺图等阻断原因。
- AI稿独立呈现待处理、可随原题入库、已采用等实际状态。原题已入库但AI稿待处理时，待办入口继续可见。
- “可入库”不改成“已人工核对”；模型判断、教师确认及已入库各有原义。
- 第一版移除综合“就绪度”百分比与四色进度，避免不同集合看起来可以直接相加。

正常情况下，原题概览可表达为“10题可入库 · 8题待核对 · 1题重复”。AI待办及缺失考查信息另外标明，不混入原题进度。

### 下一步与当前任务对应

| 当前情形 | 主要动作与反馈 |
| --- | --- |
| 原题尚待核对，无硬性阻断 | “确认原题并继续”；确认范围沿用实际内容，随后转到下一道原题待核对题。 |
| 原题有缺图、条件遗漏等阻断 | 就地说明具体问题，提供对应字段修改／材料查看；禁止确认绕过。 |
| 正在编辑原题 | 一个明确的保存入口；排版查看使用“预览排版”，不以“完成”暗示保存。 |
| AI稿有明确字段疑点 | 展开对应内容，提供该字段修改；保存不冒充AI稿已采用或已更新题库。 |
| 原题可入库、AI稿仍待处理 | 明示原题可入库与AI待办，允许沿用现有仅原题入库资格。 |
| 选择可入库题／全卷原题核对结束 | 突出“将N道原题入库”，仍打开逐题范围确认。 |
| 已入库题的AI稿修订完成 | 沿用独立“更新题库解析／继续上次解析更新”。 |

每个当前任务区域只突出一个主行动。核对中突出本题动作，整卷入库仍保留可见入口与准确数量；进入可入库视图后突出整卷入库。

## 3. 目标界面

### 顶栏与清单

- 正常阅读态顶栏最多两行：返回导入记录、试卷名称、简短原题概览、入库入口和更多操作。
- 进入审核默认收起全局组卷导航，保留返回与重新展开入口，不清空原组卷工作区。
- 题目清单保留原题号、题型、简短状态；只有具体疑点显示一句短原因。普通未查看题用中性“待核对”，不一律包装为错误。
- 主筛选使用“全部／待核对原题／可入库”；已入库、重复、未采用等从更多筛选进入。AI有待办时另保留可见数量入口，避免已入库AI待办消失。
- 补全考查信息保持整卷级可见入口及后端待补数，按需展开范围和模型调用说明；不放回单题正文，也不藏入深层菜单。
- 处理中仅显示必要阶段、已保存进度与取消；失败显示具体原因和下一步。条件性反馈不因顶栏精简而删除。
- 不在本次顺带增加试卷重命名、自动重试或新的模型设置流程。

### 原卷与正文

- 有原卷且宽度足够时默认并排。原卷区域内集中放大、缩放、页码、整份PDF、识别原文入口，移除重复的独立查看按钮。
- 保留整页与整份PDF能力，支持跨页核对；定位不可靠时明确提示，不生成猜测裁图。
- Markdown／TXT没有原页时直接展示排版，隐藏不可用的原卷切换和定位按钮。
- PDF／DOCX已有原卷信息但读取失败时，保留错误与重试入口，不按“没有原页”静默隐藏。
- 小窗口优先阅读：缩窄或收起题目清单；辅助问题区收为当前事项条或按需面板，避免整块操作栏堆在正文下面。
- 1280×720、正常缩放和正常阅读状态下，题目阅读区域可见高度目标不少于360px；长内容在其对应区域滚动，避免外层再嵌套一个相同方向的内容滚动区。

### 单题阅读与疑点

- 题面、选项、小问及原卷实际答案解析保持完整。原卷缺项不制造“答案待补”任务，不用AI稿填入原卷字段。
- 阅读顺序为题面与原卷参考、独立AI教学稿、考查信息。AI稿与考查信息按需展开；有明确疑点的内容自动展开。
- 右侧不再重复提供原题／AI领域Tab；显示当前问题清单，问题使用短来源标签，点击后联动正文对应字段。
- 同一问题只保留一份完整解释。列表和页头只显示简短状态，受限复核过程、完整原始意见和审计进入详情。
- 字段有可靠绑定时就地提示并提供修改；无法可靠定位到句段时明确为字段级核对，不猜测或改动公式内部片段。
- 考查信息无数据时合并为缺项摘要；必要疑点、已有非空内容仍可阅读，AI来源与待核状态不消失。

## 4. 编辑与保存

### 日常字段修改

- 题干、单个选项、原卷答案解析、AI答案／解析／难度依据等按确切字段进入编辑。
- 短字段使用紧凑弹窗，显示原文、修改内容、适用的必填依据和确认项；必要保存条件在首屏可见。
- 长解析提供可展开的前后对照和排版预览。公式工具仅在相关编辑器激活时出现，复用现有数学输入与富文本渲染。
- 点击图片、链接、选择文字不误触发编辑；铅笔有可读名称、键盘焦点和至少44px点击区域。
- 小问增删、顺序、题型及复杂知识／解法结构调整保留高级入口，复用现有完整编辑能力；常规修改不展开全部字段。

### 显式保存

- 输入即时保留为本窗口未保存草稿；失焦不写入源题、教学稿、审核决定或题库。
- 编辑状态只保留一个稳定保存区域，显示“未保存修改／保存中／保存失败／已保存到本机”的真实结果。
- 查看排版不等于保存，保存不等于审核通过，确认原题不等于采用AI稿，入库仍单独确认。
- 取消不写入；放弃未保存内容需明确确认。保存失败、版本变化和后台进度更新均保留已有输入。
- 原题修改后，旧AI稿按现有来源绑定规则失效；不静默重绑、不联动采用、不自动追加模型调用。
- 原题可选核对备注保留轻量入口，去掉重复确认按钮。教学疑点保留为提醒时，现有性质、四项核对与依据合同不变。

## 5. 实施顺序与文件职责

| 阶段 | 交付范围 | 进入下一阶段前的验收 |
| --- | --- | --- |
| A：状态与统计 | 提取单一展示计算入口，修复资格计数，定义原题与AI状态、筛选和下一步含义。 | 复现卷应为10题可入库、8题包含AI稿；7道未通过题不计入可入库。重复、未采用、已入库与AI待办有独立覆盖。 |
| B：阅读工作区 | 精简顶栏，默认专注布局，收敛原卷入口，正文与疑点联动，减少重复状态。 | 1280×720达到阅读高度目标；原页／整份PDF／识别原文仍可达；未知坐标不裁图；没有原页的文本记录不出现无效查看控件。 |
| C：阅读段落与编辑减负 | 按需阅读段落、原题字段编辑、紧凑AI编辑窗、复杂结构高级入口、统一保存位置。 | 普通字段不展开整题表单；必填条件首屏可见；取消、失败、版本冲突和切题均保留正确草稿；不改变原题／AI／入库边界。 |
| D：综合验证与交付 | 全链路隔离回归、实际渲染核对、产物与源码一致性检查，按仓库约定生成EXE。 | 通过下述验证矩阵后交付；不默认制作安装包，不把模拟用例当真实教师验收。 |

本次按 A、B、C 顺序完成改造，再进行 D 综合验收。用户明确不考虑遗留数据，本次未增加旧格式迁移或适配层；验证只使用新建模拟记录。

实现职责：

- `import-triage.ts`、`import-review-flow.ts`及独立展示计算模块负责展示状态和导航；Rust投影仍决定资格与允许操作。
- `ImportPaper.tsx`先保留当前会话、详情缓存、事件订阅及编辑缓冲的所有权，逐步提取页头、清单、正文和动作组件，避免一次重写整套状态。
- `SourceCompare.tsx`整合查看入口与模式，复用现有素材、原件、页码和哈希校验接口；不同时重做后端资产协议。
- `TeachingAnalysis.tsx`和字段编辑组件负责定向编辑、紧凑布局与未保存保护。原题保存与教学稿修订继续调用各自既有接口。
- 完成新交互后再移除失去用途的重复界面状态；本轮不新增整卷大请求、轮询、隐式模型检查或自动保存接口。

## 6. 验证矩阵

所有运行使用临时昵称、独立SQLite和附件目录；截图、日志及测试材料在仓库外。此前复查仅覆盖Markdown，PDF／DOCX原页体验必须补测。

| 场景 | 必须验证的结果 |
| --- | --- |
| 原题未通过但AI稿可用 | 不计入可入库，不被进度或新标签放行。 |
| 仅原题可入库，AI稿待处理 | 原题仍能按既有资格入库，AI待办保持可见，确认范围明确。 |
| 缺图、选项不全、重复、未采用 | 保持相应阻断／归类，不靠“确认”或折叠信息绕过。 |
| PDF／DOCX、跨页题、无可靠坐标 | 原件、整页、整份PDF与识别原文可达；保真校验不减免，定位不足明确显示。 |
| 公式、图片、表格与长解答 | 阅读、编辑预览及原卷内容完整；学生版不混入AI或教师内部资料。 |
| 原卷缺答案解析 | 保持空白，不额外要求教师补题或强制核对空字段。 |
| 快速切题、改选记录、A→B→A | 缓存与预取沿用精确快照；迟到响应不跳转、不覆盖草稿、不重播旧编辑请求。 |
| 同题原题与AI编辑 | 原题未保存保护可理解；保存使旧AI稿失效时明确反馈，不能自动采用旧稿。 |
| 保存失败、候选变化、修订冲突 | 保留输入、显示具体原因，阻止旧内容覆盖新版本；取消与重试含义正确。 |
| 后台事件、断线、窗口恢复 | 正常事件通知与持久状态补齐继续有效；有未保存编辑时延迟采用新详情。 |
| 已入库但AI仍待处理 | 可找到后续待办；单独更新解析，原题和冻结成卷不被改写。 |
| 键盘、输入法、弹窗 | Ctrl+Enter仅在适用阅读状态确认原题，普通Enter不全局提交；Escape、关闭和焦点行为正确。 |
| 1280×720及更宽窗口 | 正文优先、目标点击区域可用；长名称和公式不造成整页横向溢出，弹窗无多余双滚动。 |

执行检查依照改动范围：先相关前端与Rust回归、类型检查和构建，再用当前浏览器走实际Solid＋Rust隔离链路。通过后不重复跑无关昂贵测试；新增改动或失败再补相应用例。

## 7. 本轮保留边界

原件／素材所有权和哈希、修订及候选版本、原题保真、幂等保存、入库确认、模型用途与额度、未保存编辑保护、事件补齐与冻结成果均沿用现有合同。折叠或合并界面不改变任何一项资格。

新呈现已同步至 `tutor-ui.md` 和 `import-teaching-workflow.md`；实施完成与真实教师使用效果分别记录。

## 8. 实施与隔离验证记录

- 状态与入口：采用独立原题资格、AI 待办及整卷考查信息入口。19 题新建模拟卷实测原题可入库 10 题，其中 8 题包含 AI 稿、2 题仅原题；8 题待核对、1 题重复。原题未通过但已有 AI 稿的 7 题未计入可入库。
- 阅读：页头压为两行，移除混合进度条与右侧领域 Tab；默认收起全局导航。1280×720 实测正文可见高度约 483px。问题区按需打开，不占据额外正文行；原题、AI 稿与考查信息按阅读顺序呈现，难度依据问题自动展开考查信息。
- 字段编辑：原文字段保存继续使用单题 CAS／幂等接口，显式设为待确认，旧教学绑定按原合同失效。源字段与 AI 字段分别验证失败保留、显式重试、取消保护；后台更新后旧修订被拒绝，输入仍保留。直接点击候选难度依据可打开准确字段；短字段的必填依据及核对项在 1280×720 首屏可见。修正公式工具栏失焦收起造成按钮移动、第一次点击落空的问题。
- 缓存：同一快照第 12 → 13 → 12 题往返，目标详情请求数维持 3 → 3，回到第 12 题时没有详情加载占位。原题确认后进入下一道原题待核对，AI 任务仍单独导航。
