# 试卷处理阶段与错误展示

2026-10-29，用户要求处理试卷时明确当前阶段、具体错误，并区分网络／基础服务、模型、业务问题。本次修改是只读展示与诊断投影，不改变已确认的调用额度、失败恢复、人工核对或入库边界。

## 阶段

主线为接收准备文件、OCR识别及材料保存、建立整卷索引、分批转录、来源完整性校验、生成课堂教学稿、教学稿检查、按问题复核、用户核对及入库。补充考查信息是单独的显式分支。实际执行状态与已绑定请求证据提供阶段；旧记录缺少证据时显示“阶段待定位”，不按错误码中含有model就统称模型整理，也不根据界面停留时间编造进度百分比。

列表、后台任务、当前试卷详情及单题待办分别显示适用的阶段。完成一次后台任务不代表题目已入库，停在来源批次的局部草稿不冒充完整试卷。单题解析失败不冒充整卷来源失败。

## 错误分类

| 显示类别 | 包含范围 | 不能据此断言 |
| --- | --- | --- |
| 网络与基础服务 | 请求连接或响应读取失败、服务端HTTP错误／限流、模型列表、用途配置／凭据、本机转换工具或存储问题 | 超时不等于模型不会解题；没有传输证据不能断言本机断网、服务端排队或模型思考过久 |
| 模型输出与内容 | 不合法JSON、输出截断／空内容、补丁合同、可检测显示缺陷，以及具体解析质量疑点 | 格式失败不等于数学错误；自检／复核意见不等于独立核验结论 |
| 业务与原卷材料 | 来源题号覆盖、必要条件／配图／表格归属、材料疑点、内容哈希或版本冲突、发布回执 | 不能仅因来源校验失败就认定原卷有错或OCR服务有错；仍应对照原件定位 |
| 原因待定位 | 旧通用错误或新错误缺少足够定位证据 | 不按model／ocr前缀猜责任方，不以未知错误自动重试或放行 |

后端诊断保留旧stage、summary、location、nextAction与调用／断点计数，新增稳定stageKey、stageLabel、category、subcategory、serviceLabel、operationLabel、evidenceBasis、causeNote等投影字段。后台摘要使用廉价只读投影，详情在允许范围内校验已有响应哈希后补充证据。HTTP状态、模型输出格式和材料校验分别解释。

普通界面使用中文显示阶段、类别、具体原因和下一步。原始错误码、请求计数和技术资料留在详情；原始错误、请求响应、OCR和来源断点不重写。分类不改变黄红优先级、待办数量、模型复核额度或后端发布资格。

## 恢复与核对

- 网络／服务故障：检查对应服务后显式继续，复用OCR和成功断点，不自动重发或循环。
- 模型输出失败：保留完整原响应，按现有来源恢复或一次教学复核合同处理；不能为提高成功率接受残缺JSON或扩大补丁范围。
- 原卷材料／业务失败：根据具体问题核对原件或重新读取版本；不得猜补题号、条件或忽略缺图。
- 未解决的教学质量问题：保留初稿与当前原因，由用户处理；分类标签不是采纳或入库确认。
