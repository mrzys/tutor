# 学生管理与组卷学情同步方案

2026-10-21 后续调研更新：用户明确第一版先做基础能力，至少记录学生答卷。
调研过程见[答卷档案与作答证据方案](student-answer-evidence-research-2026-10-21.md)。
用户随后明确选择并确认实施 [ADR-0007](../adr/0007-student-answer-grading.md)：学生基础信息、原答卷保存、关联成卷或外部原题、后台 AI 批改、历史查看及按需教师修正。
本文件下文保留早期草案，其中“掌握状态维护、关联后自动同步学情”不再作为当前建议的首批交付范围。
下文是早期研究记录，当前实现进度以验证文档为准；组卷规则不因答卷归档或批改自动改变。

状态：草案，2026-10-21。按用户要求先给方案，本轮不实现学生管理入口或改变组卷规则。

## 目标和现状

让私教维护学生的学习进度与需要巩固的内容，在关联学生组卷时直接使用这些记录，减少重复输入。

当前桌面只支持学生姓名／昵称、可选年级和本机试卷关联，保存在 `personal.sqlite` 的 `students` 表；
支持 `@` 选择或快捷新增，尚无学情档案。组卷已有 `learnedScope`、`learnedKnowledgeUids` 和逐解法依赖检查，
可以承接教师确认的已学边界。关联学生身份目前不会发送给模型，方案不视为这条边界已改变。

## 页面布局

侧栏在“导入试卷”下方增加 Lucide `Users` 图标及“学生管理”。点击后进入独立页面，保留原组卷输入。

- 左侧学生列表：搜索姓名／昵称、年级，新增学生；单项只显示姓名、年级和最近学情更新时间，归档学生默认收起。
- 右侧学生详情：顶部姓名、年级与编辑入口；下方“学情”“练习记录”两个 Tab，默认进入学情。
- 新增继续允许只填姓名／昵称，年级使用现有下拉项。没有学情记录时显示“尚未记录”，不强制补档才能组卷。
- 归档从默认选择列表移除，保留历史试卷关联和快照；本阶段不做会连带破坏练习记录的硬删除。

## 学情记录内容

| 内容 | 操作和展示 | 组卷用途 |
| --- | --- | --- |
| 学习进度 | 沿用教材章节树，可按小节批量标记已学，并展开调整知识点；空白为未记录 | 形成已学知识与工具边界 |
| 知识掌握情况 | 叶知识点标记“未评估／待巩固／基本掌握／熟练”，支持筛选待巩固项 | 在本次考查范围内优先安排待巩固内容 |
| 记录依据 | 可填观察日期、教师备注及关联练习；明确教师记录的来源 | 让状态可追溯，避免把模型建议当已证实学情 |
| 练习记录 | 展示已关联的草稿、成卷、布置时间和教师填写的反馈 | 查看历史，辅助后续调整 |

“已学”与“掌握”分别保存。知识点待巩固仍可属于已学范围；未记录也不等于未学。
首版不显示自动生成的掌握百分比，不用年级推定实际进度，不因生成或布置过一份试卷就标为已掌握。
逐题作答录入、自动批改和长期趋势分析作为后续能力，先让教师直接记录即可。

## 关联学生时如何同步

1. 通过上方选择器或输入 `@` 选中学生，保留正文原位置的学生标签，自动读取最新本机学情。
2. 学生标签附近用轻量提示“已同步学情”，点击可展开简短摘要：已学范围、待巩固知识点、更新时间。
   详细知识点不铺满输入框；旁边提供“本次不采用”和“查看／编辑学情”。没有记录时提示尚无学情，仍可继续组卷。
3. 对于新需求，将已学知识与工具写入本次已学边界；在教师已选考查范围内，将待巩固点作为规划偏好。
   题量、用途、目标难度和本次考查范围保持教师的明确选择。
4. 若教师已经手动调整本次已学边界，或切换到另一学生，先显示本次设置与新学情的差异，由教师选择采用。
   切换不能悄悄覆盖当前明确设置。没有选择时保留当前设置，不混用两位学生的学情。
5. 需求确认页以一句话说明采用的学情，例如“已学至集合基本运算，重点巩固集合交集”；教师确认后才进入题位规划。
6. 已学边界继续由真实解法依赖检查；待巩固只影响范围内优先级，不放宽条件，不编题、不减少题量。
   考查范围与已学记录冲突时明确提示，允许教师修正进度或本次范围，不静默把未学标成已学。
7. 练习结束后，教师可在练习记录填写反馈，再确认更新对应知识点状态，形成下一次组卷的依据；
   布置记录或单次结果不会直接自动改成“已掌握”。

解除关联时只移除此次由学情带入的参数，并保留教师明确修改的字段与正文；有冲突时显示差异供选择。
单次组卷调整不反向写入学生档案。关联仍限定当前的一名学生，多学生共同组卷单独设计，不取模糊平均画像。

## 隐私和保存边界

- 学情放入 `personal.sqlite`，与 `question-bank.sqlite` 分离，不进入共享题库或题目标签。
- 建议以学生＋学科建立有修订号的学情档案；当前仅数学可用，知识点使用真实教材目录 UID。
- 每条掌握记录保存知识点 UID、状态、记录时间和依据；教材投影和细知识点分别保留身份，不能因同名就替换 UID。
- 教师确认需求时冻结本次 `learningContextSnapshot` 及学情修订号，派生草稿和成卷保留该快照。
  学情后来更新只影响新的组卷，不自动更改已确认规划、草稿、成卷或 PDF。
- 发送给模型的仅是采用后的教学参数：已学知识 UID、工具前提、范围内待巩固 UID。
  姓名、学生 ID、联系方式与自由备注不发送，也不印入试卷。规则组卷直接使用同一份本地参数。
- 保存采用修订检查与幂等操作；学生归档、重命名不破坏已有试卷快照。

## 建议首版范围与验收

先实现“学生列表＋编辑／归档＋学情手动记录＋关联后同步＋本次快照”。练习 Tab 先复用已有试卷归属，
不加入班级、聊天画像、自动诊断、在线作答或成绩预测。

模拟回归至少覆盖：新学生无档案照常组卷；关联同时同步且不覆盖正文和题量；手动设置冲突；切换与解除学生；
弱项不扩大考查范围；未学依赖继续留缺题；档案更新不改旧成果；身份不进入模型及 PDF；退出重启与修订冲突恢复。
这些验证只能证明产品行为，不代表完成真实学生学情诊断。
