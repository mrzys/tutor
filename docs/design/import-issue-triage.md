# 导入问题处理：评审汇总与实施合同

日期：2026-10-27。状态：**已实现；隔离模拟回归与实际前端操作验证通过，详见本次验证记录。不是实际教师使用或数学正确率验证。**

依据：[Kimi 评审](../review/import-issue-triage-design-review-2026-10-27.md)、此前设计提案及用户提供的其他模型评审、当前导入与教学稿合同。用户本轮要求汇总评审后开始开发。本设计不改变原题保真、教师确认、单次模型复核和数据隔离边界。

## 一、几轮评审的采纳结果

| 评审意见 | 采纳方式与修正 |
| --- | --- |
| 黄／红问题必须交给用户处理 | 原题与解析分别显示状态和原因；颜色表示处理性质，不替代后端入库资格。模型疑点仍称“模型提示”，不冒充已证实数学错误。 |
| 三栏阅读工作区 | 沿用现有导入页：左侧问题导航，中间完整题目与独立教学稿，右侧问题和可执行动作；原卷对照复用已有能力。 |
| 合格题先入库 | 复用后端精确发布资格与部分发布能力；统一确认弹窗列出实际题号及内容范围。不是新造整卷全有或全无规则。 |
| 仅原题入库 | 教师完成原题核对后仍走统一发布确认；不采用未合格 AI 稿，但保留原卷真实答案、解析与来源。不得笼统清空 `solution`。 |
| 入库后解析继续处理 | 原题版本冻结；本地独立教学草稿可继续处理，之后显式“更新题库解析”，单独确认且核对题库版本。不能把更新伪装为再次入库。 |
| 单题重试、其他题不受影响 | 只请求当前题，其他题仍可读。保留记录 CAS 和必要写入排斥，不以“单题锁”名义移除版本保护；并发写能力以实际后端合同为准。 |
| 恢复初稿 | 默认“撤销本次编辑”，恢复进入编辑时的字段；不得覆盖已保存的教师修正。恢复最初 AI 版本若提供，必须另行明确确认。 |
| 精确句段定位 | 仅凭版本绑定的字段／句段身份定位；仅有字段时定位到字段，无目标或失效时明确降级，不模糊猜句。 |
| 小屏底部抽屉 | 主要处理内容放到题目后方；抽屉用于次要操作。长公式、图片、表格不得被固定按钮遮挡。 |
| 三色闭环、立即投用 | 可作为辅助工作流实施；设计图和模拟回归不证明真实教师采用、教学效果或数学正确率。 |

## 二、状态、颜色与计数

状态投影只读取实际记录、后端资格和已保存意见；不以关键词、词表清零或模型自评证明数学正确。

- 原题：待核对、可确认入库、保真阻断、已入库。
- 解析：未开始、处理中、技术失败、待核对、合格候选、已采用、未采用。
- 重复：独立中性状态，不能重复发布，不当作数学错误或技术失败。
- 红色“需核对”：存在未解决的实质性材料、方法、推导或证明疑点。原题和解析分别标明。
- 黄色“待处理”：无红色疑点，但仍有未开始、技术失败、表达调整等可执行工作。
- 已核对为 informative 的提醒保留历史，不继续计入未解决待办；不能抹除其他问题。
- 同题有红黄问题时导航以红为优先，但详情保留各项。正常题不逐题增加“可入库”意见卡。

导航总标签使用“待办”，避免同时把总数和黄色子集都称“待处理”。过滤器为“待办／全部／已入库／重复”；必要时提供黄／红筛选。待办与已入库允许重叠，因为原题已入库后解析仍可能待核。可入库数只统计当前未发布且后端资格通过的题，不能用“全部减待办”推算。确认按钮覆盖全部当前符合资格的未发布题，首版不新增隐含勾选系统。

## 三、用户处理路径

### 1. 原题核对和首次入库

本题处理栏直接显示“确认原题”：用户对照原卷后勾选“我已对照原卷，确认本题内容完整、修正正确”，再点击“确认原题并保存”。一次确认覆盖当前原题实际包含的字段，备注选填；保存不等于发布。系统记录用户明确确认的范围与版本，不冒称独立验算或教师数学审核。内容缺失、材料硬阻断及版本冲突仍须先修正，不能靠勾选绕过。页头“确认入库（N）”打开题号清单，逐题标明“原题与原卷参考”或“含合格 AI 解析”。后端发布时重新核对身份、哈希、素材、版本和重复情况。缺图或内容丢失不可通过人工勾选绕过。

AI 稿不合格而仅原题发布时，不向题库写入该 AI 稿；原卷参考仍按原内容保存。界面区别“原卷未提供解析”和“AI 解析尚未采用”，不得谎称原卷缺项。

### 2. 人工处理解析

复用教学稿逐字段修订和逐意见核对。改动仍绑定原题和当前候选；未授权字段、原题、原卷参考不被补丁覆盖。意见确认必须有依据，不提供“忽略全部”。无法局部解决的核心方法问题保持待核，不自动循环请求模型。

切题、切记录和离页需保留或提示未保存的教学编辑。撤销只撤销本次未保存修改。已保存的教师修正、初始模型输出和旧尝试分别留存。

### 3. 显式技术重试

仅在实际技术失败且后端允许时显示。确认界面给出题号、阶段、实际配置，以及本次只生成还是另含尚未使用的首次复核。请求只含当前题的明确身份，有 `operationId` 幂等与审计；同一次网络重发不新建多次业务尝试。

不对已合格题重复请求，不自动重置既有 Qwen 额度，不因点击查看或刷新发请求，不自动转由其他模型兜底。超时只表示本机未获得有效完成响应，不断言服务商没有执行或没有计费。新候选不继承旧候选的人工核对和句段授权。

### 4. 已入库原题的解析补发布

继续处理的是本地教学草稿，不能修改已发布原题。候选通过现有必要检查后，“更新题库解析”单独确认题目及改动范围。后端绑定真实题库身份、`contentVersion`、`teacherVersion`、原题哈希及候选哈希；任何冲突都保留本地稿和题库旧内容，提示重新核对。

成功后为“原题已入库／解析已采用”；失败不降级原题入库状态、不清空草稿、不改冻结成卷或已有 PDF。该操作不重新转录来源、不重新生成答案、不自动外呼。

## 四、定位与可访问性

问题可携带 `domain`、`fieldPath`、可选 `segmentId`、`sourceContentSha256` 和 `candidateSha256`。只有与当前内容精确一致的目标才可高亮。缺少身份或内容已变时，显示“无法定位到原句段”，保留问题文字并允许手动阅读；不得把第一个相似句当成确切位置。

复用共享 token、Lucide 和 `CloseButton`。状态同时有文字／图标；键盘操作、可见焦点、Escape、至少 44px 点击区域、减少动态效果及未保存离开提示保留。窄屏按导航、题目、处理动作顺序重排，公式局部横向滚动，页面不整体横向溢出；底部动作预留安全区和滚动空间。

## 五、验证合同

本轮所有案例为模拟或回归，不对实际用户库写入，不调用真实模型验证 UI。Rust 数据测试使用临时目录；浏览器回归连接实际隔离 Rust stdio 驱动，不用假 localStorage 冒充持久化。

驱动位置：`desktop/src-tauri/src/bin/driver.rs`。构建命令：

```powershell
cargo build --manifest-path desktop/src-tauri/Cargo.toml --no-default-features --features dev-tools --bin tutor-desktop-driver
```

运行时必须设置 `TUTOR_DESKTOP_DATA_DIR` 为仓库外隔离目录。驱动以每行 `{id, action, payload}` 输入、`{id, result}` 或 `{id, error}` 输出；正式 release 不提供该驱动。开发前端沿用 `127.0.0.1:1420`，DEV 专属 `window.__TUTOR_DESKTOP_REQUEST__` 可桥接驱动。

最低验收项：

1. 计数来自统一投影；已入库解析待办、重复、informative、红黄并存和无教学稿的旧记录分别验证。
2. 只读打开、过滤、定位、对照原卷和历史不产生模型请求。
3. 仅原题发布不采用问题 AI 稿、不丢原卷参考；已入库解析后续可独立处理和显式更新。
4. 原题、候选或题库版本变更后，旧补丁、旧核对、旧定位和旧补发布请求失效，失败保留旧成果。
5. 单题技术重试目标、幂等和调用额度验证；已合格题不重跑，其他题可读。
6. 未保存的原题与教学编辑均有保护；撤销不覆盖已保存修订。
7. 批量确认弹窗列出精确题号与发布范围，后端重新判定资格。
8. 实际长题干、KaTeX、表格和题图在宽屏、窄屏和手机尺寸下可读，主操作、焦点和错误反馈可用。
9. 生产构建通过；针对新增状态、动作、失败和内容边界的测试通过后，再完成浏览器交互与控制台验证。

## 六、实施与验证记录

本轮已实现四阶段：状态导航、人工处理、显式单题技术重试、原题入库后的解析补发布。主界面仍为现有导入工作区，原题与原卷参考保持独立。

- `importTriage` 只读投影统一生成待办、已入库、重复、红黄及解析采用状态。`reviewEligibility.publicationScope` 提供后端实际首次发布范围，前端不猜测入库资格和范围。
- 所有导入详情响应增加 `teachingActions[questionId]`。`import_teaching_retry_start` 精确请求单题、仅重新生成、不自动追加 Qwen；保留旧尝试与已用复核次数。其他题可读，同卷写操作仍受后台互斥与记录 CAS 保护。
- 已发布原题的独立教学草稿可以人工修订；`import_teaching_publish` 单独确认后更新题库教学投影，校验题库内容／教师版本、原题、候选与标注哈希，不修改原卷参考及冻结成卷。
- 中断采用保存 `pendingTeachingPublication`，提供原请求恢复入口；即使题库事务已提交、导入回执未完成，也保留黄色待办，不把“已采用”当成“无需恢复”。
- 原题核对保存后仍需统一发布确认。未保存的教学字段和逐意见表单纳入切题保护；同一时间只编辑一项，防止保存一项丢失另一项输入。字段切换不得覆盖未保存文本。
- 句段无法安全映射至富文本 DOM 时只高亮确切字段并明确告知；不根据相似文字猜句。窄屏提供直达处理操作入口，处理区位于题目之后，底部保存栏不固定遮挡内容。

验证记录：[实施与隔离验收](../review/import-issue-triage-implementation-2026-10-27.md)。真实模型服务、真实教师使用及重新评估题库数学质量不在本轮 UI 回归范围内。


## 七、2026-10-27 紧凑复核与稳定布局

- 页头保留试卷名称、题数及确认入库；原卷 PDF、重新检查和补充考查信息收进“更多试卷操作”。说明、处理记录和模型细节按需展开。
- 左侧题号、正文和本题处理栏保持固定网格；普通题和疑点题均保留处理栏，避免正文宽度及公式换行随状态跳动。长题与长问题列表分别在自己的区域滚动，页头、筛选和底部保存状态不随内容变化。
- 原题确认是两个明确操作，无需重复填写固定依据和多项常规确认；AI 解析修订保持单独入口，原题确认不等于 AI 稿已被采纳。最终入库仍由页头单独确认。
- 不缺省显示“原卷缺少解析”等通用说明；原卷参考与 AI 解析始终分开保存。缺图、缺题、重复及失败信息继续显示。
- 设置、题库、组卷和学生页使用一致的可收缩容器与稳定滚动条空间；选项切换不改变外层宽度。设置的模型／思考选择框保留固定高度。移动窄屏显示上下阅读／处理区域，长公式在局部滚动，不压缩或丢弃正文。
- 原题确认沿用记录 CAS、幂等及 Rust 素材校验。客户端不得伪造或改写 `sourceAssetBindingAudit`；审核保存从旧记录恢复这一程序维护字段，避免确认一道题时删除其它题的题图绑定审计。

## 八、2026-11-01 人工处理入口精简

- 本题处理区按“原题／AI解析”分区，分别显示具体疑点与相应操作。正文保留短状态和绑定的疑点高亮；重复原因、调用过程及审计不再常驻，完整记录按需展开。
- 从原题疑点进入修改时，定位到其绑定的题干、选项或小问字段。原题编辑优先显示题面，原卷参考与考查标注收起；不会以 AI 内容填充原卷缺项。
- AI 修改默认只显示当前字段的编辑框、修改依据和确认项；原文及排版对照按需展开。取消恢复编辑前内容，保存失败保留输入，成功后收起编辑器。
- 原题确认与 AI 修改继续独立；缺失材料、修订版本、未保存内容及核对依据的既有门禁保持。分区、折叠和文案精简均不改变后端入库资格。
- 空闲审核不重复显示处理阶段。题号、对照区和操作区保持固定框架，长内容由各自阅读区滚动；切换处理分区与详情页签不改变外框尺寸。

本次为隔离副本上的界面回归，非真实教师验证；未请求 OCR 或模型，未修改正式用户数据。验证材料保存于本机维护目录 `import-review-simplify-20261101-01`。
