# 对比评审：当前 UI vs DESGIN.md（Ollama UI 设计规范）

- 评审时间：2026-10-14
- 对象：`DESGIN.md`（ollama-ui-design v1.0，桌面与项目根目录为同一文件）vs 当前 tutor-v1 线上 UI
- 前置报告：`ui-ux-review-2026-10-13.md`、`ui-visual-review-2026-10-13.md`

## 结论

**两者不是"两个设计"，是同一个设计的"完成版"和"半成品"。** 规范作为体系明显更好；你感到的"别扭"不是风格方向错了，而是当前 UI 迁移到这套规范的一半——三代样式层同时存活，规则在页面间随机漂移。

关键证据：项目里已经存在 `web/tokens.css`，其 token 与 DESGIN.md 几乎同源（`#525252` 正文、PingFang 字体栈、pill 圆角、12px 容器圆角、caption 13px），说明团队早已选定这个方向；但 `styles.css` 第 1 行（Inter/`#000`/5px 直角按钮/Georgia 品牌字）和第 7 行（system 字体/`#525252`/pill 按钮）两代旧层仍在生效，三层叠加靠源码顺序赌结果。

## "别扭感" ↔ 规范条款对照

每一条别扭都能在规范里找到对应的 MUST 条款被违反：

| 别扭感 | 当前现状（出处） | 规范条款 | 严重度 |
|---|---|---|---|
| 按钮有的方、有的全圆 | 5px / 8px / 9999px 混用（styles.css 两层 button 规则互相覆盖） | §1.3 一切可交互元素 MUST 9999px，8px 仅下拉面板 | 高 |
| 小字多、发虚 | 11px 键盘提示、12px 元信息、`tokens.css --font-small:12px` | §2.2/§3.8 最小 13px，「12px 已废弃」 | 高 |
| 文字深浅不一 | 正文 `#000`（第一层）vs `#525252`（第二层），随页面漂移 | §1.7 正文 MUST `#525252` | 高 |
| 行高忽紧忽松 | `line-height:1.6`（第一层）vs `1.75`（第二层） | §3.1 中文正文 MUST 1.75（1.5/1.6 会"挤成砖墙"） | 中 |
| 浮层有"浮起感" | 历史悬停卡、账号菜单、下拉均带 `box-shadow`（5 处） | §1.4 MUST NOT 用阴影做层级，只允许发丝线或反相 | 低 |
| 圆角 7 档并存 | 4/5/6/8/12/14/9999px | §2.4 收敛为 0/6/8/12/9999 五档且各有唯一用途 | 中 |
| 字号 19 档 + 全局缩小补丁层 | styles.css 末尾 `.app-main` 覆盖块 | §2.2 固定 11 档字阶 | 中 |

已符合规范的地方（不用动）：`tabular-nums` 数字处理、无 italic/uppercase/300 字重/`break-all`、语义色只用琥珀 `#b45309` + 红 `#dc2626`、画布纯白无渐变、题干 16px/1.85 阅读排版（超过规范 1.75 要求）、`prefers-reduced-motion` 已有兜底。

## 规范对 tutor-v1 的适用性裁剪

规范是给"营销站 + Agent 控制台"写的，tutor-v1 是高密度工作台，直接全盘照搬有三处需要决策：

| 规范条款 | 与现状/产品的冲突 | 建议 |
|---|---|---|
| §1.2 品牌色 MUST 只有纯黑 | 上一份视觉评审曾建议"引入品牌色"解决 CTA 与标题同权重问题 | **二选一，需要拍板**：采纳规范则放弃品牌色，识别度靠字标/吉祥物路线；本题库工具属性强，我建议服从规范 |
| §2.1 焦点环 MUST 实心蓝 `#3b82f6` | 当前是 `#171717` 黑环（对比够但突兀感低） | 服从规范换蓝环——这是规范里唯一允许的"准强调色"，也顺带缓解全站无色彩锚点的问题 |
| §2.2 `body-md` 16px 为正文默认 | 工作台密集页面（题库表格、试卷编辑）当前正文 14px | 兼容：规范自带 `body-sm 14px` 用于表格/列表，题库/试卷页用 `body-sm`，阅读型内容（题干 16px）不动 |
| §4-§8 中定价/计费/终端/代码块章节 | tutor-v1 无此场景 | 忽略，不影响其余条款生效 |

## 收敛路线（建议执行顺序）

1. **删旧层**：移除 `styles.css` 第 1 行与第 7 行两个 `:root` 主题层及连带的基础元素规则，让 `tokens.css` 成为唯一 token 源。（对应视觉评审问题 9）
2. **tokens.css 对齐规范两处偏差**：`--font-small: 12px` → 提到 13px（或直接删除该档）；`--control-radius: 8px` → 交互元素改 pill，8px 仅保留下拉面板。
3. **按规范 §9 检查清单全站过一遍**：重点扫 11/12px 小字、圆角混用、`box-shadow` 浮层。
4. **顺带修复前两份报告的交互项**（组卷篮 LaTeX、进行中列表命名、按钮语义），避免 token 翻新后旧交互问题被新皮盖住。

工作量评估：第 1-2 步是纯粹的删除与变量替换，风险低、收益最大（直接消灭"三层叠加"这个别扭总根源）；第 3 步是逐页巡检，适合拆成多次提交。

## 一句话回答"哪个好"

DESGIN.md 好，而且好得不是一点——它是可判定、可检查、可交给 Agent 执行的完整体系；当前 UI 是它未完成的实现。要消除别扭，方向不是换设计，而是**把实现收敛到规范**。
