# ADR-0001 review

- 评审对象：`docs/adr/0001-assembly-workflow.md`（草案，待讨论），对应 PR #1
- 评审日期：2026-10-10
- 评审结论：**框架成立，建议采纳为讨论基线**；3 处 P0 阻塞落地，7 处 P1 造成实现期歧义。
- 评审方式：仅基于文档本身，不假设已有实现或外部约束。下文行号均为本 PR 中 `docs/adr/0001-assembly-workflow.md` 的行号。

## 总体判断

这份 ADR 的质量高于多数"草案"：职责切分（决策二）、"未知不等于零"（决策四/七/八）、题位身份与展示题号分离、确认分层与失效传播（决策七）、可观察的验收场景表，都是真正能约束后续设计的部分。尤其是"不得把旧报告作为当前通过结果"和"不得为凑难度配额诱导模型改判"这两条，说明作者清楚这类系统最容易在哪里失真。

主要问题不在写错了什么，而在**三类边界没有判定规则**：整卷级目标归谁所有、什么算"必需目标"、什么情况下允许"接受未知"。这三条共同决定"教师能不能成卷"，而文档把它们分散在决策五/七/八里互相引用，实现时会出现两种相反的正确实现。

另外有一个命名问题（"协同"）和一个逃生阀缺失（无降级交付），建议在采纳前处理。

## 必须澄清（P0）

### F1. 标题里的"协同"在正文中不存在

> L1：`# ADR-0001：教师协同组卷 workflow`

全文没有任何第二个教师角色：无权限、无评论、无移交、无审阅分工。正文实际描述的是"教师 + 系统的协同"。

这会直接影响 ADR-0002 的表设计（是否需要 `owner_id` / `collaborator` / 评论表）和范围判断。建议二选一，并同步改标题：

- **改名**："教师组卷 workflow（人机协同）"，把"协同"限定为教师与系统的分工；
- **或显式排除**：在 L22 的排除项里追加——

> L22：`...首版不建设题库管理、学生作答闭环、实测难度校准、自动题干改写或通用 Agent 编排平台。`

补一句："首版为单人教师操作；多人协作、评论与权限移交不在范围内。"

倾向前者——如果后续真要做多人协作，那应该是一份新 ADR，而不是从这份里长出来。

### F2. 整卷级目标属于"需求"还是"蓝图"，未定义

这是本次评审**最需要修的一条**。

> L59：`| 需求 | 本次为什么组卷，以及整卷教学约束 | 年级、主考范围不能替代已学边界 |`
> L60：`| 蓝图 | 每个题位应该考什么、承担什么任务 | 计划题数和目标安排不能当作实际覆盖 |`

下面这些东西既不是题位任务、却决定题位任务，归哪一边都说得通：

- "分类讨论至少两题"
- "按当前题量重新分配难度"
- "训练重点：数形结合"
- "题型配额：8 选择 + 4 填空"

归属不定会让决策七的失效传播出现两种相反实现：

- 归需求 → 改难度分布 = 需求变化 = 蓝图回到待确认 + 全部重检；
- 归蓝图 → 改难度分布 = 蓝图内调整 = 只重检受影响题位。

而本文同时支持两种读法——决策五把"分类讨论至少两题"当**整卷要求**处理（L113），又把"按当前题量重新分配难度"当**蓝图内的相关难度目标**处理（L114）：

> L113：`| “分类讨论至少两题” | 对应目标及承担任务的题位 | 显示计划和实际覆盖缺口，只调整必要题位 |`
> L114：`| “按当前题量重新分配难度” | 相关难度目标 | 先展示分布与受影响题位，确认后同步应用；保留无关题与锁定 |`

建议在 L59 补一句，之后 L113/L114 按同一规则归类：

> 整卷级目标（训练重点、题型配额、难度分布、"至少 N 题"类要求）属于需求；蓝图负责把这些目标分解并落到具体题位。目标本身变化按需求变化处理（蓝图回到待确认）；仅题位任务变化按蓝图变化处理（只重检该题位及其绑定）。

### F3. "必需目标"没有判定规则，直接决定能否成卷

> L156：`5. 必需目标的规划缺口与决定性不符合已解决。仅因目标依据未知而不足时，允许教师针对当前检查、目标和依据明确接受未知；仍显示未知，不计为证实覆盖。此决定不能绕过缺图、版本变化、内容错误或明确超纲等门禁。`
> L157：`6. 检查与评估对应当前依据。选填偏好未满足、可接受的适配建议与已明确接受的未知保持可见，不能一律升级为内容错误。`

两条门禁一个说"必需目标"、一个说"选填偏好"，但全文没说怎么区分。后果很实际：教师说"想要两道分类讨论题"，题库只有一道——判必需则成卷被拒，判选填则带缺口成卷。同一句话，两种结局。

唯一靠近判定的表述在 L84：

> L84：`...教师明确提出"必须覆盖、至少 N 题"时形成可检查的目标约束；...`

这只覆盖了"教师显式硬性表述"一种来源，没覆盖系统推荐、模板默认值、无法判定三种情况。建议补：

| 表述来源 | 判定 | 缺口时的处理 |
| --- | --- | --- |
| 教师显式硬性表述（"必须""至少 N""不允许"） | 必需目标 | 阻断成卷，须解决或明确接受未知 |
| 系统推荐、难度倾向、教学建议 | 选填偏好 | 保持可见，不阻断 |
| 模板/预设带入的默认值 | 选填，除非教师再次显式确认 | 保持可见；UI 须标明来源 |
| 无法判定 | 澄清，不默认 | 不得默认成必需，也不得默认成选填 |

同时把决策四/八里被当作已知概念使用的三类缺口补上判据：

- **规划缺口**：蓝图层面就无法安排（题位数目/结构/题型与规格自相矛盾）→ 必须在蓝图里处理；
- **供给缺口**：蓝图安排得下，但题库没有足够合格候选 → 可见缺口，不自动放宽；
- **证据缺口**：有题，但匹配依据不足 → 走"接受未知"路径，与上述两类分开计数。

## 建议修订（P1）

### F4. "接受未知"可能变成万能后门

> L156：`...仅因目标依据未知而不足时，允许教师针对当前检查、目标和依据明确接受未知；仍显示未知，不计为证实覆盖。此决定不能绕过缺图、版本变化、内容错误或明确超纲等门禁。`

限定方向是对的，但风险在于：只要把一项检查包装成"依据未知"，就都能被接受放行。建议再加三条闸门：

1. 仅适用于**已有具体题目、但匹配证据不足**的情形；连候选都没有的不适用（那是供给缺口，不是未知）。
2. **逐项接受**，不允许整卷批量接受；每次接受记录目标、题位、依据与操作人。
3. 接受后该目标仍显示为未知，**不计入已证实覆盖**，也不得在报告汇总里被"已处理"字样掩盖。

### F5. "全部题位已审阅"作为硬门禁，与效率目标冲突

> L154：`3. 当前题目均已完成教师审阅；受影响的失效审阅已重新处理，锁定不能替代审阅。`

20+ 道题逐题点一次，成本不低。而验收末节明确要求比较效率：

> L222：`效果验证记录教师完成可接受试卷的总用时、重复填写、不必要换题、满意题保留和最终采纳，并与教师现有组卷方式比较。仅功能走通不能证明效率改善；...`

两条放在一起，首版很可能测出"功能走通但更慢"。建议在本文就给出首版取舍：

| 选项 | 含义 | 代价 |
| --- | --- | --- |
| A. 维持逐题全审阅 | 最严格，可追溯性最好 | 成卷成本高，效率验收风险大 |
| B. 批量审阅 | 同屏/分组批量确认，仍逐题记录 | 需定义批量粒度与失效粒度 |
| C. 降级为"已进入审阅视图" | 成本最低 | 与"锁定不能替代审阅"的严谨度不匹配 |

倾向 B，并补一条规则：**批量审阅后，任一题发生换题/任务变化，只失效该题的审阅，不波及同批其他题**（与决策七末段"单题变更不会撤销其他无关题目的有效审阅"保持一致）。

### F6. "锁定 ≠ 审阅"被强调了三次，说明概念本身反直觉

决策五、决策七、决策八各强调一次，例如：

> L118：`锁定表示禁止自动替换当前绑定，不表示题目正确或已经审阅。...`
> L154：`...锁定不能替代审阅。`

一篇文档需要三次澄清的区分，通常是建模信号而不是文档问题。建议加一条收敛原则，之后正文只保留一处说明：

> 锁定是替换保护开关（禁止自动换题），审阅是教师判断记录（确认看过并接受本题）。二者正交：可锁定未审阅，可审阅未锁定。UI 可以合并呈现，状态机必须分离。

### F7. 缺少降级交付路径

> L159：`若任何门禁失败，保留当前草稿，返回具体题位或整卷问题及可操作入口，不要求重新组卷。...`

门禁很完整，但没回答：**题库就是不够时，教师能拿到什么？** 现在的答案是"保留草稿 + 返回问题入口"，但现实中教师常需要一份"带缺口的卷子"先拿去用。

建议明确二选一：

- 支持**受限交付**：导出/打印带缺口标注的草稿卷，显著标注未满足项，且不进入"已成卷"状态、不参与冻结与版本；
- 或显式写"首版不支持带缺口交付，缺口必须在成卷前解决"。

倾向前者，但要求与"成卷"严格区分命名（例如"草稿导出"而非"成卷"），否则会污染决策七的冻结语义。

### F8. 增删题位是否触发蓝图重确认，两处表述不一致

决策七说蓝图在"题位任务或规格变化"时需重新确认：

> L136：`| 蓝图 | 当前逐题任务与整卷结构可作为执行依据 | 题位任务或规格变化，或依赖的边界确认失效 |`

增删题位属题位任务变化，据此应重确认。但决策五只说保留/同步规格，未提重确认：

> L110：`| “增加两道填空题” | 新增题位及相应整卷结构 | 普通组卷同步题量；有考试规格时先更新规格；保留原有题位与绑定 |`
> L111：`| “这个题位不要了” | 明确删除的题位及绑定 | 展示结构影响后删除；有规格时同步规格，涉及锁定题须明确授权 |`

建议在 L110/L111 各补半句"并使蓝图回到待确认"，或明确例外（例如"新增空白题位不触发重确认，直到填入任务"）。

### F9. 提案部分可应用时的路径未定义

> L126：`同一组相关状态修改要么整体提交，要么不提交，并记录事件。...不能提交一半规格或声称全部匹配成功。...`

缺的是：一次自然语言请求被解析成 N 个变更，其中 1 个校验失败时怎么办。建议明确为：**差异先整体展示，由教师勾选子集后一次性提交**；未勾选的不应用也不留残状态。这样与"整体提交或不提交"不冲突（提交单元是教师勾选后的集合）。

### F10. 并发冲突后"继续编辑"的行为未定义

> L146：`...写操作带版本，冲突时保留教师未提交输入并提示刷新核对，不静默覆盖其他窗口的修改。`

方向正确，但没说冲突状态下继续点保存会怎样。建议补一句：**冲突未解决前，禁止任何写提交**；教师须显式选择"重载最新版本"或"以我的为准强制覆盖"（写入事件日志并标记版本跳跃）。

## 建议补充的验收场景

| 场景 | 必须可观察的结果 |
| --- | --- |
| 要求"分类讨论两题"，题库 0 题 | 缺口可见且不静默放宽；判为必需时成卷被拒，判为选填时带缺口成卷并标注 |
| 同一题或同题簇被两个题位命中 | 去重生效，第二个题位保持未填或换到簇外题，不出现两处同题 |
| 删除一个涉及考试规格的题位 | 规格同步更新并提示结构影响；不留下题数与分值不一致的草稿 |
| 一次自然语言请求含 3 项变更，其中 1 项校验失败 | 三项差异全部展示并标明失败项；教师勾选可应用项后一次提交，正式状态不因失败项残留 |

## 建议的处理顺序

1. 先定 F1（命名）和 F2（目标归属）——这两个不定，其余修订会反复。
2. 再定 F3 + F4（必需性判定 + 接受未知边界），它们是同一套规则的两半。
3. 然后 F5 + F7（审阅成本 + 降级交付），建议带着试点教师一起定。
4. F8–F10 属文字对齐，可在采纳时一并改。
5. F11–F15 不阻塞采纳，可作为采纳后的第一轮修订。
