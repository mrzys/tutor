# 正式试卷导入与教学解析质量收口

2026-10-26用户授权修复正式导入，并将`codex/core-flow-review-followup`的全部已完成功能改动提交、合并到本地`master`。本次不推送远端，不迁移或更新实际个人库，不重复处理已核对通过的题目。以下是工程及真实接口回归，不是真实教师使用或教学效果证据。

## 正式导入

普通PDF／DOCX上传复用原有后台任务、PaddleOCR和原件／素材审计；新来源任务使用`indexed_parallel_v2`：

1. DeepSeek Flash/low根据紧凑OCR块和实际原页建立全卷索引，识别整题、跨页小问、对应原参考和非题材料。
2. 短题最多3道、解答题单道；3个常驻worker完成后领取下一批。来源阶段共用每次显式操作120秒截止，包含该阶段实际模型列表、排队和传输，不包括OCR、教学稿或人工核对。
3. 所有外呼前，主线程先保存尝试身份；SQLite不跨worker。成功批次逐个保存，未完整的卷不产生可审核题目。取消、失败和退出保留进展，显式继续只处理未完成批次。
4. 实际完整HTTP 200/stop已保存、正式审计或checkpoint尚未保存时，核验原始请求、来源范围及实际PNG后本地恢复，不重新请求模型。正式审计使用原子落盘，原stream文件保持不变。
5. 整卷完整性、素材角色和原卷参考映射仍校验。普通有`sourceStructuring`的导入发布前也必须重放完整来源审计，不能仅在“恢复过”的记录中检查。

来源阶段不生成答案、课堂解析、难度或知识关联；原卷确有的参考答案解析保真保存。独立教学稿仍在来源完整后生成。缺失的正式知识关联保持未知，由已有显式“补充考查信息”入口处理；不增加自动补标调用。TXT／Markdown和旧成功断点保留实际旧协议及已有标注，不因新流程重新生成。

此前20卷来源试验的入库率不能直接充作这份正式接入代码的实测质量。本次正式路径另外以隔离HTTP／SSE回归核验，包含真实PNG投递、旧断点、乱序完成、取消、截断、stream-only崩溃窗口和发布篡改拒绝。

## 教学稿不再仅按术语判断

- 正式教学候选仍为原7字段。DeepSeek同一次响应可带`qualitySignals`，分别报告数学、证明、方法、讲解和难度考查疑点；不新增独立初审调用。
- 教师或明确授权代理发现的具体问题，须绑定当前原题和候选哈希，才能进入复核记录。没有敏感术语的实际问题也可使用尚未用过的一次Qwen额度；旧已用额度不重置。
- 表达问题只修相关文字；数学／证明／方法问题允许修复相关推导、结论及必要教学字段。难度档位、要求列表或材料问题在首次调用前选择适当的完整稿合同，不在补丁失败后追加模型调用。
- 新质量补丁使用`fieldHashMode`：按题目、原题、候选和单字段哈希校验，模型无需逐字回抄长段原文。越权、错哈希、无实际推导修改或未解决问题仍阻断。历史`oldText`模型合同和教师手动修订合同继续严格重放，不自动放宽。
- 模型逐项“resolved”、自检全pass、JSON合法和术语清零都不是独立数学核验。未知语义不冒充正确，`ready_candidate`仍只是未发现具体阻断的候选；原有确认入库边界保留。
