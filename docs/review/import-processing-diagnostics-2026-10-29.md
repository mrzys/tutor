# 试卷处理阶段及错误分类回归

2026-10-29。用户要求处理试卷时明确当前阶段与具体错误，并区分基础服务、模型、业务问题。本轮实现只读诊断和UI展示，没有发起新的OCR、模型请求或试卷处理，没有发布题库，也没有启动第二批。

## 交付

- 后台任务、导入历史、当前试卷、失败详情及单题待办显示实际阶段。
- 错误大类为网络与基础服务、模型输出与内容、业务与原卷材料、原因待定位；详情进一步说明配置、通信、服务、本机环境、格式合同、来源材料或版本一致性。
- 具体原因、涉及操作、失败题号、已保存断点和下一步分别显示，原始错误码保留在错误详情。超时不被直接解释成模型不会解题，来源检查失败不直接断言原卷有错。
- 失败的补充考查信息任务使用该次操作的错误与证据，不借旧来源失败解释新问题。
- 来源完整性校验前增加真实保存的source_validating状态；其余阶段依据现有状态和确切请求证据，不编造百分比或已完成结果。
- 已用一次复核的单题明确提示人工核对／修改，不暗示可以自动追加Qwen。窄屏更多操作菜单补回原有重新解析入口，不新增重试策略。

分类不改变题目内容、原始错误、成功批次、黄红优先级、审核资格、复核额度和入库权限。程序分类和规则通过均不等于独立数学核验。
