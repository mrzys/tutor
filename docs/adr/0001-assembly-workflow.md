# ADR-0001：教师协同组卷 workflow

- 状态：草案，待讨论；本文不表示功能已经实现或决策已经采纳。
- 创建与更新日期：2026-10-10。
- 适用项目：Tutor v1。
- 后续依赖：ADR-0002「题库与蓝图详细设计」，计划中。

## 背景

教师组卷通常从一个教学场景开始：为刚学完的章节做检测，为某种方法安排训练，或准备阶段测验、综合模拟。教师先提出大致要求，看到蓝图和真实题目后继续调整，最终确认一份可用试卷。

因此，组卷需要保留教师多轮审题的成果。只要修改一点要求就重新生成整卷，会丢失满意题、锁定和审阅记录；只按知识点、题型和难度拼题，也不能说明实际覆盖了教师要求的训练任务。

Tutor v1 是从零设计的教师协同组卷项目。本 ADR 定义其首版 workflow：以需求表达教学意图，以稳定题位安排考查任务，以具体题目形成试卷草稿，通过局部调整和明确确认完成交付。字段和检索细节留给下一份 ADR。

## 范围与目标

首版覆盖教师从提出需求、确认蓝图、审题与调整，到确认成卷、输出学生版和教师版的完整工作流。

判断成功的依据是教师能否获得符合当前教学要求、内容可用且可以复核的试卷，以及修改过程中能否保留无关的满意题。覆盖教学目标只说明提供了相应考查机会，不证明学生已经掌握，也不证明训练效果。

本文不展开题库表结构、接口 DTO、完整蓝图字段、难度评估提示词、页面视觉稿或导出技术。首版不建设题库管理、学生作答闭环、实测难度校准、自动题干改写或通用 Agent 编排平台。

## 决策一：使用可往返的工作台流程

```text
快速收集需求
    ↓
生成蓝图草案 + 题源供给预检
    ↓
教师确认可执行蓝图
    ↓
按题位匹配，形成试卷草稿
    ↓
教师审题与局部调整 ←→ 修改相关需求或题位
    ↓
更新检查与整卷评估
    ↓
教师确认成卷 → 冻结版本 → 输出学生版 / 教师版
```

这些环节表示业务职责，不要求对应多个强制跳转页面。教师可以在同一工作台切换蓝图视图和试卷视图；返回修改要求时保留当前草稿，不能把“返回”解释为“重新开始”。

| 环节 | 进入条件与主要输入 | 系统产出 | 教师操作与进入下一环节的条件 |
| --- | --- | --- | --- |
| 需求对齐 | 教师选择场景，点选或补充要求 | 可编辑需求，标明默认、建议、沿用和待澄清项 | 核对关键输入；信息不足时可保存草稿、生成待确认蓝图 |
| 蓝图规划 | 当前需求草稿 | 逐题任务、结构汇总、供给预检及缺口 | 调整并确认当前版本；已学边界等执行条件须有效 |
| 草稿组装 | 当前蓝图已确认 | 题位与具体题目的绑定、匹配依据、未填题位 | 查看实际选题；题源不足时停留在草稿，不伪造完整卷 |
| 审题与调优 | 已有草稿，允许部分题位未填 | 局部修改结果、保留题目、冲突与待核对项 | 换题、调整本题任务或整卷要求；规格变化后重新确认相关蓝图 |
| 检查与评估 | 当前需求、蓝图、绑定及证据 | 确定性检查、目标覆盖、未知项和教学建议 | 逐题审阅，处理阻断项及需要教师决定的事项 |
| 成卷与交付 | 当前版本满足最终门禁 | 冻结的成卷记录及两种输出投影 | 教师明确确认成卷；后续调整通过复制为新草稿进行 |

检查可以在审题过程中持续运行，不要求教师每换一道题就手动走完整流程。最终确认始终复核当前版本。

## 决策二：需求、蓝图、选题和评估分别负责自己的事实

| 对象 | 唯一职责 | 不允许混用的事实 |
| --- | --- | --- |
| 需求 | 本次为什么组卷，以及整卷教学约束 | 年级、主考范围不能替代已学边界 |
| 蓝图 | 每个题位应该考什么、承担什么任务 | 计划题数和目标安排不能当作实际覆盖 |
| 试卷草稿 | 每个题位实际选了哪道题，以及教师审阅和锁定 | 实际选到的题不能反过来静默改写原要求 |
| 检查与评估 | 当前选题对当前要求的符合情况及依据 | 未知、建议或模型估计不能写成已证实通过 |
| 成卷记录 | 教师最终确认的需求、蓝图、题目和顺序版本 | 后续题库变化不能静默替换已冻结题目 |

题位有稳定身份，显示题号只是当前顺序。排序、增删或换题不改变无关题位身份；自然语言中的“第 3 题”按指令所对应的展示版本解析，无法确定时局部澄清。

详细身份、版本、字段、枚举、唯一权威和一致性校验由 ADR-0002 定义。

## 决策三：先收集足以执行的需求，细节允许逐步补充

收集顺序为“场景 → 教学年级或目标考试 → 主考范围 → 已学边界 → 题量与时长 → 可选难度倾向与训练重点”。常用需求通过点选、可见预设和沿用配置完成，文字与图片补充特殊要求。

| 场景 | 范围入口 | workflow 特别要求 |
| --- | --- | --- |
| 同步检测 | 教材、章节、知识点 | 按当前教学进度检查题源适配；复习和模拟题作为备选须显式允许 |
| 专题训练 | 知识点或方法专题 | 可跨章节，重点落实为可观察的训练任务 |
| 阶段测验 | 已学章节和知识点 | 允许跨章、跨册，检查覆盖、题型与时长 |
| 综合模拟 | 高考复习或考前冲刺、目标考试结构、复习范围 | 确认结构化考试规格；允许复习、模拟和高考题源，仍需检查边界与内容 |

首屏常驻显示已学边界摘要、关键排除、来源及确认状态。主考范围回答“主要考什么”，已学边界回答“解题时允许使用什么”。仅年级、当前章节或沿用上次配置均不能推断本次全部已学，也不能沿用旧会话的确认。

缺少必要信息时只追问影响当前执行的一项，保留其他输入。边界尚未明确或确认无效时，允许保存待确认蓝图，不能确认可执行蓝图或宣称超纲检查通过。

难度倾向、能力与素养不是所有教师的必填问卷。难度可明确选择“不指定”；系统推荐目标保持建议属性，确认整个蓝图不自动把建议升级为必需要求。教师明确提出“必须覆盖、至少 N 题”时形成可检查的目标约束；任务歧义须澄清，缺少标准标签但任务明确时仍可根据实际题目核对。

综合模拟的考试规格须明确有序题型大题、逐题分值和总时长，题数、题型配额与总分由程序派生。仅考试名称或自由描述不足以确认。已配置规格时，增删题、改题型、顺序或分值涉及规格的修改，须同步更新规格与相关题位，避免两处各自维护。

快速收集的控件、模板、难度整数分配与澄清交互可在后续专题 ADR 细化；本 ADR 先确定其输入输出和确认边界。

## 决策四：蓝图确认前预检供给，确认后按题位匹配

蓝图先描述逐题任务，再从题库检索具体题目。供给预检按当前场景、范围、边界、题型和题源策略给出候选情况；预检数量不代表去重后一定能填满，也不代表目标已证实覆盖。

- 未完成或失败的预检显示“待检查”或“检查未完成”，不能用零代替未知。
- 结构或必需目标的规划缺口须在蓝图中处理；单纯候选供给不足可以保留为可见缺口，不能自动放宽范围、切换场景或降低目标。
- 匹配保留已符合要求的绑定，检查题型、范围、解法依赖、题面可用性与内容版本，再考虑任务、挑战程度和全卷覆盖，并排除同题及重复题簇。
- 解法依赖按可行路径核对：存在符合当前已学边界的有效解法时，不因另一条解法使用未允许知识而直接拒绝；关键解法依据不足仍显示未知。
- 实际结果分别统计未填、明确不符、依据未知与有依据支持；候选数、计划数和实际覆盖数分开显示。
- 没有候选时，新增题位保持未填；已有题位保留原题并标明与新要求的匹配缺口，不能报告换题成功。

供给预检绑定当前需求与检查时的题库状态；需求或题源变化后重新检查，不把历史“有题”或“缺题”当作本次结果。

## 决策五：修改按明确范围执行，保留其他成果

| 教师操作或反馈 | 修改范围 | 预期行为 |
| --- | --- | --- |
| “这道题不喜欢，换一道” | 当前绑定 | 排除当前候选并换题，保持题位任务；不扩大为全卷知识排除 |
| “要求基础题，但选来的太难” | 当前绑定 | 修正选题不匹配；不反改蓝图来迁就实际题目 |
| “这个位置改成提高题” | 当前题位及绑定 | 更新题位目标，重检或重匹配本题；其他题保留 |
| “增加两道填空题” | 新增题位及相应整卷结构 | 普通组卷同步题量；有考试规格时先更新规格；保留原有题位与绑定 |
| “这个题位不要了” | 明确删除的题位及绑定 | 展示结构影响后删除；有规格时同步规格，涉及锁定题须明确授权 |
| “全班没学过这个定理” | 整卷已学边界及受影响绑定 | 展示边界差异并重新确认，重检全部相关题，不清空整卷 |
| “分类讨论至少两题” | 对应目标及承担任务的题位 | 显示计划和实际覆盖缺口，只调整必要题位 |
| “按当前题量重新分配难度” | 相关难度目标 | 先展示分布与受影响题位，确认后同步应用；保留无关题与锁定 |

修改规格会使蓝图回到待确认；仅换具体题目不会撤销已确认的蓝图要求。教师可以先编辑和保存草案，但新的可执行版本需要确认，受影响旧匹配与审阅不能继续作为通过依据。

锁定表示禁止自动替换当前绑定，不表示题目正确或已经审阅。锁定题与新要求冲突时，保留题目并展示冲突；教师可明确解除锁定或授权本次换题。允许记录例外的建议项可保留教师决定；确认的内容错误和决定性硬约束失败仍须解决。

## 决策六：自然语言提出方案，程序校验并执行

自然语言交互采用“理解需求 → 提出结构化变更 → 展示作用范围与差异 → 教师应用 → 程序执行 → 回显结果”。聊天记录不是正式试卷状态；教师通过 UI 直接点击“换题”等按钮时，该操作本身表达对应授权。

LLM 负责整理输入、提出题位任务和有限的局部修改建议，必要时提供教学适配分析。程序负责标识解析、范围和版本校验、检索、去重、数量汇总、锁定保护、最终门禁及持久化。LLM 不覆盖整份会话 JSON，也不自行确认、放宽要求或最终放行。

同一组相关状态修改要么整体提交，要么不提交，并记录事件。检索结果不足属于明确业务结果：可以整体保存教师新要求及其缺口；不能提交一半规格或声称全部匹配成功。后台检索或评估在写回前校验版本，过期结果不覆盖新状态。

模型不可用时保留手动编辑、确认和审题路径；程序无法校验的模型输出显示失败，不伪造执行结果。有限操作协议及幂等、事务边界在详细设计中定义。

## 决策七：确认分层保存，按相关依据失效

| 确认对象 | 确认意味着什么 | 何时需要重新确认或重检 |
| --- | --- | --- |
| 已学边界 | 本次允许使用的知识及适用上下文已被教师认可 | 边界、适用年级或场景、相关解析依据变化；范围扩展超出边界或无法判断时 |
| 考试规格 | 当前结构、逐题分值和总时长已确认 | 规格内容变化；仅换题或调整教学任务不使规格失效 |
| 蓝图 | 当前逐题任务与整卷结构可作为执行依据 | 题位任务或规格变化，或依赖的边界确认失效 |
| 逐题审阅与具体决定 | 教师审阅了当前题目及其匹配上下文 | 更换题目，或相关任务、范围、题目内容、解法及匹配证据发生变化 |
| 最终成卷 | 当前需求、蓝图、顺序和绑定通过门禁并冻结 | 已成卷版本只读；修改另建草稿并重新检查 |

确认已学边界不等于题目依赖检查通过，确认蓝图不等于选题已经满足，锁定也不等于逐题审阅。单题变更不会撤销其他无关题目的有效审阅；只改题数、分值或排序等无关项不重复确认已学边界。

评估绑定当前需求、蓝图、绑定和证据依据。依据变化后旧报告标为待更新，历史仍可查看；不得把旧报告作为当前通过结果。难度评估与题位目标比较分开，不能为凑齐难度配额诱导模型改判；未经校准不显示为实测答对率。

题位未指定难度目标时省略该项匹配，实际难度未知本身不触发待审阅或“接受未知”操作；范围、内容与其他明确目标仍照常检查。未经独立教师验证的模型档位只作为建议，不直接成为可靠硬筛选依据。

保存需求、题位、绑定、教师决定、版本及操作事件到组卷业务库。写操作带版本，冲突时保留教师未提交输入并提示刷新核对，不静默覆盖其他窗口的修改。

## 决策八：最终成卷由明确门禁控制

教师点击“确认成卷”时，服务端复核当前版本，至少满足：

1. 已学边界确认有效，蓝图为当前已确认版本；综合模拟具有完整且已确认的考试规格。
2. 所有必需题位已填，实际题型与结构一致，题量、配置的分值、顺序和时长投影没有冲突。
3. 当前题目均已完成教师审阅；受影响的失效审阅已重新处理，锁定不能替代审阅。
4. 题目内容版本、学生题面就绪、来源及素材身份通过当前题库复核；确认的内容错误和明确范围违规没有被教师普通确认掩盖。
5. 必需目标的规划缺口与决定性不符合已解决。仅因目标依据未知而不足时，允许教师针对当前检查、目标和依据明确接受未知；仍显示未知，不计为证实覆盖。此决定不能绕过缺图、版本变化、内容错误或明确超纲等门禁。
6. 检查与评估对应当前依据。选填偏好未满足、可接受的适配建议与已明确接受的未知保持可见，不能一律升级为内容错误。

若任何门禁失败，保留当前草稿，返回具体题位或整卷问题及可操作入口，不要求重新组卷。详细设计须将题位、目标与题库复核组成完整的成卷检查，不能仅凭题数完整判定通过，也不能将接受未知表述为全部要求已有依据支持。

成卷保存确认时的需求、蓝图、顺序、题目版本和必要证据引用，形成可追溯身份。业务上冻结本次组卷结果，不修改题库发布或审核状态。题库访问保持只读，具体接入方式与读取合同由 ADR-0002 决定。

学生版只提供题面、题号及需展示的分值；教师版在相同题目顺序上提供可用答案、解析和必要提示。数据投影在服务端分离，不能只靠前端隐藏答案。教师参考答案或解析缺失时明确显示，不编造内容；首版不把答案解析齐全作为普通学生版成卷的统一前置条件。

已成卷内容不可静默漂移；重新打开或交付时发现题库身份、素材可用性变化，应提示并按交付边界处理，不能替换为最新题面。可重建快照、重新取素材及具体输出格式在 ADR-0002 或后续交付设计中细化。

## 工作台需要支持的反馈

- 常驻摘要：场景、年级或目标考试、主考范围、已学边界与确认状态，以及计划、已填和待处理数量。
- 蓝图视图：结构、逐题任务、目标分配、供给情况和未解决缺口。
- 试卷视图：真实题面、本题目标、简短来源，以及换题、调整本题要求、锁定、审阅入口。
- 检查与评估入口：分别查看内容问题、配置冲突、目标缺口、适配建议和未知项，并定位相关题位。
- 变更回显：说明修改了哪些要求与题目、保留了多少题，以及尚未解决什么。

小屏保留边界摘要和主要操作，细节进入抽屉或分视图；不以复杂页面布局作为 workflow 正确性的前提。

## 考虑过的替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 每次需求变化重新生成整卷 | 无法保护满意题、锁定与审阅成果，增加重复劳动 |
| 固定线性向导，调整必须从头开始 | 实际审题会反复回看目标，阶段返回不应该重置成果 |
| 只有整卷简报与题目列表 | 难以稳定表达逐题任务、局部修改和目标缺口 |
| LLM 直接生成最终试卷并判定完成 | 缺少确定性版本、内容、范围和成卷门禁，无法可靠解释局部修改 |
| 首次要求填写全部能力、素养和难度细节 | 提高起步负担，未必符合教师当前任务；细节应允许逐步补充 |

## 影响与实施顺序

实现需要管理题位、绑定、确认依据及评估失效。收益是局部修改有明确对象，教师决定可以追溯，无关题目得以保留。供给不足和证据未知仍会影响交付，workflow 负责暴露并提供处理路径，不承诺自动补齐。

1. 讨论并采纳本 ADR 的流程、确认与成卷边界。
2. 创建 ADR-0002，定义题库读取、蓝图题位、绑定、匹配与版本合同。
3. 跑通手动输入、蓝图确认、题库组装、审题换题与成卷的完整路径，优先保证修改不清空成果。
4. 增加供给反馈、局部目标调整和评估更新，再接入有限自然语言提案。
5. 按实际复杂度拆出快速需求收集、难度评估或交付专题 ADR。

上述为首版实施建议；具体开发任务在相关 ADR 确认后拆分。

## 验收场景

| 场景 | 必须可观察的结果 |
| --- | --- |
| 普通教师只点选常见设置开始 | 能形成可编辑蓝图；默认和建议来源可见，不强制填写能力素养 |
| 只有年级、主考章节或沿用旧配置 | 边界显示待确认；可存草案，不可确认可执行蓝图或宣称超纲通过 |
| 综合模拟只有考试名称 | 明确缺少结构；不能确认可执行蓝图 |
| 供给预检失败或无足够候选 | 失败和零候选分别显示；缺口可见，不静默换场景或放宽边界 |
| 10 道题中仅替换第 3 题 | 原题位任务及其余 9 题绑定、有效锁定和审阅保持；本题重新审阅 |
| 调整题号后引用“原第 3 题” | 根据展示版本映射题位；不能确定时先澄清 |
| 改要求但没有替代题 | 新要求和缺口被保存，原题保留且标明不匹配，不报告换题成功 |
| 修改与锁定题冲突 | 显示冲突，不自动换题、解除锁定或清空草稿 |
| 增加两题或修改考试分值 | 结构与相关题位同步更新；保留无关题，规格与蓝图按影响重新确认 |
| 修改整卷边界 | 保留题目，重检相关绑定；未知依赖不因确认边界而变成通过 |
| 训练重点至少两题，实际一题支持、一题未知 | 分别显示计划、支持和未知；不宣称两题已证实覆盖 |
| 难度不指定或只改目标配额 | 不指定不阻断；不改写独立难度估计来凑配额 |
| 聊天提出调整或模型失败 | 提案未应用前正式试卷不变；失败后仍能手动编辑 |
| 多窗口或后台返回旧版本 | 提示版本冲突或丢弃过期写回，不覆盖新状态 |
| 成卷前题目版本、素材或就绪状态变化 | 最终复核拒绝，保留草稿并指明问题 |
| 接受某项目标依据未知 | 决定绑定当前依据，报告继续显示未知；不能绕过内容门禁 |
| 输出学生版和教师版 | 顺序一致；学生响应不携带答案与教师记录，教师版缺项明确 |
| 成卷后继续调整 | 原成卷版本保持只读，通过新草稿产生后续版本 |

效果验证记录教师完成可接受试卷的总用时、重复填写、不必要换题、满意题保留和最终采纳，并与教师现有组卷方式比较。仅功能走通不能证明效率改善；首版不以学生成绩提升作为已验证成果。

## 下一轮讨论与后续 ADR 接口

本文先提出可审阅的 workflow 基线，以下事项保留为后续输入：

- 第一阶段是否先以一种教学场景完成端到端验证；四类场景的产品边界已写明，试点范围尚未确定。
- ADR-0002 需明确题库供给和证据能力、题目与稳定题位的绑定关系，以及哪些检查可以确定执行、哪些必须保留未知。
- 教师版答案解析缺项的具体展示、下载格式及冻结素材的交付方式，在详细设计中落实。
- 若快速收集的模板、图片补充或局部澄清交互需要独立决策，再创建对应 ADR；不在本文提前确定页面控件。
