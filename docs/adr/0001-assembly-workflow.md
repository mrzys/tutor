# ADR-0001：教师组卷 workflow

- 状态：草案，待讨论；本文不表示功能已经实现或决策已经采纳。
- 创建与更新日期：2026-10-10。
- 适用项目：Tutor v1。
- 后续依赖：ADR-0002「题库与蓝图详细设计」，计划中。

## 决策速览

- 教师就是用户；首版由单个用户与系统配合完成组卷。
- 主流程：收集需求 → workflow + LLM 推导蓝图 → 用户确认蓝图 → 检索并生成试卷草稿 → 有限手动调整 → 用户确认交付。
- 需求保存整卷意图，蓝图把意图分解到题位，草稿保存实际选题。
- 蓝图确认后，主要操作是换题、增减某类题目和调整难度，目标是减少用户操作。
- 用户直接操作就是本次修改的授权，不因局部调整反复要求确认整份蓝图。
- LLM 标注有风险的题目并说明依据，用户决定保留、替换或调整要求；不要求逐题点选“已审阅”。
- 最终以用户手动调整后的试卷为准，原始要求和未满足项保留供对照。
- 系统保证修改与交付内容一致，不把缺题、未知或执行失败报告为成功。

## 背景

教师组卷通常从一个教学场景开始：为刚学完的章节做检测，为某种方法安排训练，或准备阶段测验、综合模拟。用户先提出大致要求，看到蓝图和真实题目后继续调整，最终确认一份可用试卷。

组卷需要保留用户满意的题目。修改一点要求就重新生成整卷，会增加重复劳动；只按知识点、题型和难度拼题，也不能说明实际提供了哪些训练机会。

Tutor v1 是从零设计的教师组卷项目。本 ADR 定义首版 workflow：从需求推导蓝图，再根据蓝图搜索题目形成草稿，用户通过少量、明确的操作完成调整。字段与检索细节留给下一份 ADR。

## 范围与目标

首版覆盖从提出需求、确认蓝图、调整草稿，到确认成卷、输出学生版和教师版的完整流程。成功依据是用户获得可接受的试卷，且修改过程中保留无关的满意题、减少重复填写和确认。教学目标覆盖表示提供了考查机会，不证明学生已经掌握或训练有效。

首版为单用户操作；多人协作、权限移交，以及同一组卷在两个浏览器 Tab 同时编辑不在范围内。本文不展开题库表结构、接口 DTO、完整蓝图字段、难度评估提示词、页面视觉稿或导出技术。首版不建设题库管理、学生作答闭环、实测难度校准、自动题干改写或通用 Agent 编排平台。

## 术语

| 术语 | 本文含义 |
| --- | --- |
| 需求 | 用户的组卷目的、主考范围、已学边界和整卷要求 |
| 蓝图 | workflow + LLM 根据需求生成的结构与逐题任务计划 |
| 题位 | 蓝图中一道题的位置与任务；身份稳定，显示题号随排序变化 |
| 绑定 | 某个题位当前选用的具体题目与内容版本 |
| 草稿 | 当前题位、绑定、顺序及用户调整组成的试卷 |
| 锁定 | 防止系统自动替换当前绑定的保护开关 |
| 风险 | 内容、适配或匹配依据等需要用户判断的问题，含依据不足 |
| 成卷 | 用户确认当前内容后保存的固定版本，作为交付依据 |

## 决策一：以一次蓝图确认启动组卷，围绕草稿调整

```text
快速收集需求
    ↓
workflow + LLM 推导蓝图，并预检题源供给
    ↓
用户确认蓝图及需求摘要
    ↓
按题位搜索题目，生成试卷草稿
    ↓
用户有限调整 ←→ 更新匹配结果与风险提示
    ↓
用户确认当前试卷 → 保存成卷版本 → 输出学生版 / 教师版
```

这些环节表示业务职责，不要求对应多个跳转页面。蓝图确认后自动进入检索与草稿组装，不再单独确认“开始搜索”。用户可在同一工作台查看蓝图与试卷；返回修改时保留当前成果。

| 环节 | 系统产出 | 用户操作 |
| --- | --- | --- |
| 需求收集 | 可编辑需求摘要，标明用户输入、预设和系统建议 | 点选或补充影响执行的要求 |
| 蓝图规划 | 逐题任务、结构汇总、供给预检和缺口 | 调整并一次确认蓝图及当前需求摘要 |
| 草稿组装 | 实际题目、匹配依据、风险与未填题位 | 查看结果，按需要换题、增减题目或调难度 |
| 局部调整 | 修改结果、保留题目、更新后的结构与风险 | 处理有风险题目；满意题无需重复确认 |
| 成卷交付 | 当前内容摘要、未满足项和可生成的输出 | 确认当前试卷；后续修改从成卷版本建立新草稿 |

检查与评估在后台随修改更新。系统不把每次更新变成新的用户审批步骤。

## 决策二：区分初始规划、当前草稿与实际证据

| 对象 | 负责保存的事实 | 边界 |
| --- | --- | --- |
| 需求 | 组卷目的及整卷目标：范围、训练重点、题型配额、难度分布、“至少 N 题”等 | 主考范围不能替代已学边界；系统建议不能冒充用户明确要求 |
| 蓝图 | 将整卷目标分解到题位，安排题型、任务、难度目标和结构 | 计划安排不等于实际选题已经覆盖 |
| 草稿 | 实际选题、当前顺序、锁定及用户调整 | 用户手动调整形成当前结果；保留与初始规划的差异 |
| 检查与评估 | 当前内容对要求的符合情况、依据、风险与未知 | 已处理不等于已证实；模型估计不能当作实测结果 |
| 成卷记录 | 用户最终确认的内容版本与必要上下文 | 后续题库变化不能静默替换已确认题目 |

需求是初始规划的输入，蓝图负责分解；它们不能在用户手动调整后强迫草稿恢复原样。例如用户删除一道填空题，当前蓝图结构与统计同步减少，初始题型配额保留为对照，不继续作为必须补回该题的自动命令。用户主动重新规划整卷时，再以其确认的新要求为依据。

题位具有稳定身份，显示题号只是当前顺序。排序、增删、换题不改变无关题位身份。自然语言中的“第 3 题”按指令对应的展示版本解析；无法确定时仅澄清该对象。

首版将含小问的大题视为完整题目，整体选入或替换，不单独拆换小问。共享材料的多题组合须保留题库提供的完整关系；若题库无法表达该关系，不假装组合已完整。题目、题组、重复题簇及版本身份的具体合同由 ADR-0002 定义。

## 决策三：收集足够执行的需求，避免额外问卷

收集顺序为“场景 → 教学年级或目标考试 → 主考范围与已学边界 → 题量 → 可选难度倾向与训练重点”。常用要求通过点选、可见预设和沿用配置完成，文字与图片补充特殊要求。只追问影响当前执行的缺项；已有输入始终保留。

| 场景 | 范围入口 | 特别要求 |
| --- | --- | --- |
| 同步检测 | 教材、章节、知识点 | 按当前教学进度匹配题目，显示题源与适配风险 |
| 专题训练 | 知识点或方法专题 | 可以跨章节，将重点分解为可观察的训练任务 |
| 阶段测验 | 已学章节和知识点 | 可以跨章、跨册，检查覆盖与题型安排 |
| 综合模拟 | 目标考试、复习范围和考试结构 | 提供可调整的考试规格预设，显示题型、逐题分值、总分与时长 |

主考范围回答“主要考什么”，已学边界回答“解题时允许使用什么”。摘要显示边界、排除项及其来源；仅凭年级或章节不能声称已知全部已学知识。需要沿用或推导的配置在蓝图摘要中展示，随蓝图一并确认，不另设逐字段确认手续。尚不明确的解法依赖保留为风险，不能宣称超纲检查通过。

同步检测、专题训练和阶段测验可以不指定分值、总分或时长，未指定时不虚构这些数值。综合模拟可从考试规格预设开始调整；仅有考试名称且无法获取结构时，明确补充所需结构，不假装已生成标准模拟卷。配置了逐题分值时，总分由当前题目分值汇总，不再单独维护一份冲突的总分。

难度、能力与素养不是必填问卷，难度可以选择“不指定”。用户明确提出的要求、模板默认与系统建议分别标明来源；确认蓝图不把建议升级为不可更改的硬要求。整卷目标用于指导规划和解释缺口，最终是否接受偏差由用户决定。

快速收集的控件、模板和澄清交互可在后续 ADR 细化。

## 决策四：从蓝图检索题目，诚实反馈缺口

蓝图先描述题位任务，再检索具体题目。供给预检按当前场景、范围、边界、题型和题源策略给出候选情况；候选数量不等于去重后可填满，也不代表实际覆盖了目标。

| 结果 | 含义与处理 |
| --- | --- |
| 规划缺口 | 题位安排与需求存在差异或内部结构不一致；说明差异，修正内部矛盾后展示可执行蓝图 |
| 供给缺口 | 已安排任务，但合适候选不足；显示未填题位及可选处理 |
| 证据缺口 | 已有题目，但匹配依据不足；显示未知与风险，交由用户判断 |
| 检查未完成 | 检索或评估失败、尚未返回；显示待检查或失败原因，不能记为零候选 |

自动匹配优先考虑题型、主考范围、解法依赖、题面可用性与内容版本，再考虑任务、挑战程度和整卷覆盖；排除同题及重复题簇。解法依赖按可行路径核对：存在符合已学边界的有效解法时，不因另一条解法超出边界而直接判定超纲；关键依据不足时保留未知。

候选不足时，可以展示接近要求的备选题，并明确指出题型、难度、范围等差异，由用户选择是否采用。系统不静默放宽范围、降低目标或切换场景。新增题位无候选时保持未填；换题失败时保留原题，不报告换题成功。

计划数量、实际选题、依据支持的覆盖和未知分别统计。预检与评估关联当时的输入及题库状态；变化后更新，不沿用历史结论冒充当前结果。

## 决策五：蓝图确认后提供有限调整，用户决定当前结果

首版主要操作限定为换题、增减某类别题目、调整题目或局部难度，并支持顺序、分值与锁定等必要编辑。界面直接操作即为相应授权；不因这些修改统一退回“待确认蓝图”。

| 操作 | 作用范围与结果 |
| --- | --- |
| 换一道题 | 仅替换当前绑定，保留题位任务；失败保留原题 |
| 手动选择备选题 | 按用户选择更新本题，保留备选差异和风险，不静默修改整卷要求 |
| 增加某类题目 | 新增题位与绑定，同步当前题量、题型及配置的分值统计，保留原有题目 |
| 删除题目 | 删除明确指定的题位与绑定，同步当前结构和统计，不自动补回 |
| 调整本题难度 | 更新本题目标，重检或重匹配本题，保留其他题目 |
| 调整局部难度分布 | 展示受影响题位，用户应用后仅调整该范围，保留无关题与锁定 |
| 调整顺序或分值 | 同步题号、结构与总分，不触发无关题目的重新匹配 |

锁定只防止自动换题，不表示题目已被验证。用户直接对锁定题换题或删除，已表达对该题的修改授权；系统不得借此改动其他锁定题。新要求与锁定题冲突时保留题目并提示，由用户决定。

改变整卷范围、已学边界、教学场景或考试规格属于重新规划入口，不能由一次局部换题隐式触发。系统展示差异和受影响题目，用户一次应用后重检相关绑定，保留无关成果。原始考试规格与手动调整有偏差时显示差异，不宣称仍完全符合原规格。

最终以用户手动调整为准。系统同步当前结构，保留初始要求和用户决定供对照；不为迁就选题而偷偷改写历史需求，也不强迫用户反复确认同一个修改。

## 决策六：LLM 标注风险，用户处理需要判断的问题

LLM 在组卷和调整后分析题目适配，标注需要用户处理的风险，例如疑似内容问题、解法超出已学边界、难度偏差、训练目标依据不足。风险须关联具体题位或整卷目标，提供简短原因和可查依据，避免只给一个不可解释的分数。

用户可以换题、删除、选择备选、调整要求，或决定保留当前内容。处理后记录决定；未知仍显示未知，偏差仍显示偏差，不将“用户保留”统计为“检查通过”。相关内容改变时更新风险；无关题目不重复要求处理。

难度估计与题位难度目标分别保存，不能为满足配额而改判题目。未经校准的模型难度只作建议，不显示为实测答对率；题位不指定难度时，不因此新增处理步骤。

需要人工判断的门禁以风险提示和处理入口呈现，由用户解决。用户最终确认当前试卷时可以一并确认保留摘要中已展示的风险，不另设逐项“接受未知”审批。不要求所有题目逐题点击“已审阅”，不新增批量审阅状态机。无风险标注也不等于系统保证题目正确。

## 决策七：自然语言提出有限变更，程序保持状态一致

自然语言交互采用“理解请求 → 提出有限变更并展示差异 → 用户应用 → 程序执行 → 回显结果”。聊天记录不是正式试卷状态；提出建议不自动修改草稿，用户直接点击界面操作则无需再走同一提案确认。

LLM 负责需求整理、蓝图推导、局部建议与风险判断。程序负责对象解析、检索、去重、范围与版本检查、数量汇总、锁定保护、保存与输出。LLM 不覆盖整份会话 JSON，不自行确认成卷。

首版不提供任意变更组合的勾选子集编辑器。一次请求包含多个修改时，先约束到支持的有限操作；无法确定的对象或不支持的操作说明原因。相互依赖的修改作为一个提交单元，校验失败整体保留原状态；独立操作可分别通过现有入口完成，不自动应用未获授权的剩余部分。

相关结构与绑定要么整体保存，要么不保存。候选不足属于业务结果：可以保存用户调整后的任务及缺口，不能只保存一半结构或声称已成功换题。

后台检索、评估和提案关联输入版本；单窗口内用户已继续操作时，过期结果不能覆盖新状态，需丢弃或重算。这是异步结果保护，不扩展为双 Tab 编辑冲突或强制覆盖流程。

模型不可用时保留手动选题、编辑与确认路径；失败明确回显，不伪造结果。详细操作协议、幂等、保存与版本合同由 ADR-0002 定义。

## 决策八：确认当前内容并保持交付真实

用户确认成卷前，系统展示当前题目结构、风险、原要求的未满足项及教师版缺项摘要。最终确认针对当前实际内容；用户无需先恢复初始蓝图，也无需补齐未指定的偏好。

- 供给不足时，用户可手动选备选题、减少题量或调整难度；按调整后的内容确认，不增加“降级交付”审批状态。
- 未填题位不会生成虚构题面。用户可以补题或删除空题位后确认现有题目；成卷不包含无题面的空占位，不把缩减后的试卷称为原计划已完整满足。
- 教学适配风险与目标缺口由用户决定，不由模型永久拒绝成卷；摘要与记录保留实际差异和用户决定。
- 程序确认内容可保存、结构及统计一致、题面与必需素材可用于所选输出，并且输出对应用户确认的版本。题面缺失、素材无法取得或保存失败时，明确说明无法完成的部分并提供处理入口，保留草稿，不虚构成功。
- 旧评估明确显示待更新；无法完成的新评估显示未知。最终摘要必须反映当前版本及这些状态，不把历史通过结论作为当前依据。

成卷保存确认时的需求上下文、当前蓝图、顺序、题目版本、风险与用户决定，形成可追溯身份。组卷只读取题库，不修改题库发布或审核状态。后续调整通过成卷版本建立新草稿。

学生版提供题面、题号及配置的分值；教师版按相同顺序提供可用答案、解析和必要提示。数据投影在服务端分离，学生响应不携带教师答案或内部记录。教师版答案或解析缺失时在确认摘要和输出中明确列出，不编造，也不把齐全答案解析作为普通学生版交付的统一前提。

已成卷内容不可静默漂移。交付时题库版本或素材状态发生变化，应说明影响并让用户选择处理，不能偷偷替换为最新题面。快照与素材保存、重新取用及输出格式由 ADR-0002 或后续交付设计细化。

## 工作台需要支持的反馈

- 常驻摘要：场景、范围、已学边界，以及当前题量、未填与风险数量。
- 蓝图视图：结构、逐题任务、供给与规划差异。
- 试卷视图：真实题面、本题任务、来源，以及换题、增减、调难度与锁定入口。
- 风险入口：优先定位需要处理的题目，说明原因、未知和用户决定。
- 变更回显：修改了什么、保留了哪些题、还有哪些缺口。

小屏保留摘要和主要操作，细节进入抽屉或分视图；不以复杂布局作为 workflow 正确性的前提。

## 考虑过的替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 每次调整重新生成整卷 | 丢失满意题并增加重复劳动 |
| 固定线性向导，调整必须从头开始 | 不符合查看实际题目后继续修改的过程 |
| 只有整卷简报与题目列表 | 难以稳定表达局部任务与修改范围 |
| LLM 直接生成并确认最终试卷 | 无法保护用户决定，也无法保证保存和输出一致 |
| 逐题全审、未知逐项审批、局部修改重复确认蓝图 | 增加操作负担；首版采用风险提示与用户最终决定 |
| 首次填写全部能力、素养与难度细节 | 提高起步负担；细节应允许逐步补充 |

## 影响与实施顺序

实现需要管理稳定题位、绑定、用户决定、版本与评估依据。收益是局部修改有明确对象，满意题得以保留，风险与差异可以解释。题库供给和证据能力影响自动组装质量，系统负责暴露问题并提供用户处理路径，不承诺自动补齐。

1. 讨论并采纳本 ADR 的流程、有限操作与用户决定边界。
2. 创建 ADR-0002，定义题库读取、题目与题组、蓝图题位、绑定、匹配及版本合同。
3. 跑通需求、蓝图确认、检索草稿、手动调整、风险处理与成卷路径。
4. 验证局部修改保留成果，再完善供给反馈与有限自然语言提案。
5. 按复杂度拆出快速需求收集、难度评估或交付专题 ADR。

上述为首版实施建议，具体开发任务在 ADR 确认后拆分。

## 验收场景

| 场景 | 必须可观察的结果 |
| --- | --- |
| 只点选常见设置开始 | 形成可编辑蓝图，来源可见，不强制填写能力素养 |
| 沿用配置或仅提供年级、章节 | 摘要显示边界依据和未知，随蓝图确认；不假称超纲已通过 |
| 确认蓝图 | 自动检索并形成草稿，不再要求确认开始搜索 |
| 普通组卷未指定分值与时长 | 可以继续，不虚构总分或时长 |
| 综合模拟只有名称且无可用预设 | 明确补充结构，不声称符合标准考试规格 |
| 预检失败或候选为零 | 分别显示失败和供给缺口，不静默放宽条件 |
| 10 道题仅替换第 3 题 | 其余 9 题及锁定保留，不要求全卷重新确认或逐题审阅 |
| 换题无候选 | 原题保留，明确未换成功；接近要求的备选显示差异供选择 |
| 删除一道填空题或增加两题 | 当前结构、题号与分值同步，保留无关题，不统一退回蓝图确认 |
| 含小问的大题换题 | 整道题及小问一起替换，不拆坏题目关系 |
| 两个题位命中同题或重复题簇 | 自动组装去重，不能把重复候选当作两份独立供给 |
| 用户调整与锁定冲突 | 自动流程保留锁定题，用户可直接决定对该题换题或删除 |
| 原要求分类讨论两题，实际仅一题支持或无候选 | 显示覆盖与供给差异；用户可手动调整或保留当前内容，不谎报达标 |
| LLM 标注风险或匹配依据未知 | 用户能定位并处理；保留后仍显示风险或未知，无全题审批要求 |
| 难度不指定或改变难度目标 | 不指定不增加手续；不篡改独立难度估计来凑配额 |
| 一次请求含三个相关修改，其中一个校验失败 | 整个提交单元不保存，说明失败原因，原状态保留 |
| 单窗口异步检索晚于用户新操作返回 | 旧结果不覆盖当前草稿，用户新操作保留 |
| 教学目标变化或评估失败 | 旧报告待更新，新结论未知，不把旧通过结论冒充当前结果 |
| 草稿有空题位、缺题面或必需素材不可用 | 显示具体问题；补题、删题或恢复素材后交付，不生成虚构题目 |
| 学生版与教师版输出 | 顺序一致，学生响应不携带答案；教师版缺项在确认前与输出中明确 |
| 成卷后继续调整 | 原版本固定，新草稿产生后续版本 |

效果验证比较用户完成同类组卷任务的总用时、必要操作、重复填写与确认、不必要换题、满意题保留和最终采纳。与现有手动组卷方式比较时记录任务、题量与题源条件；具体试点人数和测量方案后续制定，不预填效果数据。功能走通不等于效率改善，首版不以学生成绩提升作为已验证成果。

## 下一轮讨论与后续 ADR 接口

- 是否先选一种教学场景验证端到端流程，试点范围待确定。
- ADR-0002 需明确题库供给与证据能力、题组粒度、蓝图和绑定、用户调整同步、版本及交付一致性。
- 教师版缺项展示、下载格式及冻结素材交付方式在详细设计中落实。
- 快速收集的模板、图片补充或澄清交互需要独立决策时，再创建对应 ADR。
