## 文档约定

- 状态使用“草案、已采纳、已取代”；创建草案不代表已经采纳或实现。
- 每份 ADR 记录核心问题、范围、决策及理由、替代方案与代价、成立前提和验证依据；区分已选方案与待验证能力。
- 评审聚焦重要决策与可行性；字段、页面、异常回显及边缘情况在详细设计或开发任务中落实，仅在出现新的重要取舍时新增 ADR。
- 流程、关系和依赖图使用 Mermaid，避免用纯文本箭头代替相关图表。
- 小幅澄清在原文更新并记录日期；推翻已采纳的关键决策时新增 ADR，互相注明取代关系。
- 每份 ADR 独立说明决策依据，不以其他项目的文件、实现现状或迁移要求作为前提。
