# Tutor v1 ADR

本目录记录 Tutor v1 从零设计的项目决策。先确定教师组卷 workflow，再细化题库与蓝图合同；新增专题按讨论进度拆分，不提前固化尚未确定的需求。

## 设计顺序

| 顺序 | ADR | 状态 | 负责回答的问题 |
| --- | --- | --- | --- |
| 1 | [ADR-0001：教师组卷 workflow](0001-assembly-workflow.md) | 草案，待讨论 | 要解决什么组卷问题，选择什么流程与分工，依赖哪些成立前提，如何验证可用性 |
| 2 | ADR-0002：题库与蓝图详细设计 | 计划中，尚未创建 | 题库读取与标签能力、知识前置依赖、蓝图基线与草稿版本、绑定、匹配依据及执行结果如何落地 |
| 后续 | 快速需求收集等专题 | 按需新增 | 当交互或规则需要独立决策时再拆分，不阻塞第一份 ADR 的讨论 |

第二份 ADR 以第一份的流程和职责边界为输入。若详细设计发现流程冲突，先记录问题并修订对应决策，不能在字段或代码中静默改变产品行为。

## 文档约定

- 状态使用“草案、已采纳、已取代”；创建草案不代表已经采纳或实现。
- 每份 ADR 记录核心问题、范围、决策及理由、替代方案与代价、成立前提和验证依据；区分已选方案与待验证能力。
- 评审聚焦重要决策与可行性；字段、页面、异常回显及边缘情况在详细设计或开发任务中落实，仅在出现新的重要取舍时新增 ADR。
- 小幅澄清在原文更新并记录日期；推翻已采纳的关键决策时新增 ADR，互相注明取代关系。
- 每份 ADR 独立说明决策依据，不以其他项目的文件、实现现状或迁移要求作为前提。
