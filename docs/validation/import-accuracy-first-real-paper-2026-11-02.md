# ADR-0010：2024 北京数学卷真实服务试导入

2026-11-02，按用户“随机找一张原卷导入，再生成 EXE”要求执行。本记录是单卷真实服务检查，不是教师使用案例，也不是 40 题放量试点或数学／教学准确率结论。

## 材料与真实执行

- 从本机两份真实原始数学 PDF 中使用系统随机数选中 `raw/2024_beijing_math.pdf`，不重抽。原件 512,580 字节，2 个 A3 页面，21 题，无原答案解析。
- 原件 SHA256：`fe91257042db6f0bf77dac5c15bccf4621e3ced801f9a5aef1d8ed993d192bd5`。
- 通过原文件上传对应的 Rust `import_accuracy_start` 入口，实际调用已保存的 PaddleOCR-VL-1.6、DeepSeek Flash 及阿里云百炼 `qwen3.7-flash`。没有旧题 JSON 代替原件，没有模型列表前置、自动换模型或自动重试。
- 使用临时昵称及隔离个人库，复制现有题库快照及加密配置。在隔离配置中显式绑定新增用途；日常模型配置不修改。
- 21 题来源整理完成，整卷索引与分批转录共 12 次实际请求。此后显式策略继续复用 OCR、来源批次和仍有效的证据；v1／v2／v3 使用同一父预算，已用额度不重置。

v2 只发送题目对应的真实 OCR 块坐标，并继续发送实际原页及裁图，解决重复整页 OCR 文字超出原 24K 限额的问题。v3 冻结完整难度标准，明确核验报告的字段合同；未知用量继续保留最坏预留，但允许在剩余预算内处理其他题。OCR 及最终题目／教学信息合同未改。

第 21 题的来源核验确实检出了转录差异：原页集合定义的外大括号位于偶数条件之后，候选提前闭合，改变条件绑定范围。已再次视觉核对原页，保留该题待处理，未根据“能猜出原意”放行。

模型同意、完整 HTTP、JSON 可解析和程序合同通过均不能作为数学准确率。未对全部待处理题的实际数学稿及教学字段完成独立裁决，不计算危险放行率或正常题误阻断率；17 个技术失败不能算 17 道数学错误。统计及复核使用原卷 `sourceLabel`，不从技术 `questionId` 后缀推断原题号。
