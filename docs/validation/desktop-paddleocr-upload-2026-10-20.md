# 桌面上传试卷接入 PaddleOCR（2026-10-20）

本次验证普通 `import_prepare` 上传流程，不使用旧题 JSON 回填题面，不代表真实教师使用或已完成数学审核。
版本：0.1.22。实际用户数据库、已有导入记录和题库未修改；新结果均保存在隔离临时目录。

## 实现

- 设置新增“试卷识别”，PaddleOCR 接口、识别模型、API Key 与 LLM 配置分别保存。
  密钥使用 Windows DPAPI；不回显、不继承 LLM 密钥，不自动采用旧项目凭据。
- 普通 PDF 直接上传识别；DOCX 使用已安装 Word／LibreOffice 转 PDF 后识别，缺少工具明确提示。
  原件保留，转换 PDF 绑定原件与内容哈希，可在审核界面打开对照。
- PaddleOCR Markdown、原始版面块、原页图和真实图表裁图进入本地来源清单；
  当前 LLM 负责拆题及标注。题号、图表完整性、来源身份和素材字节分别校验，不能由模型声明绕过。
- 原始识别与模型尝试分开审计。OCR 成功而 LLM 失败时，显式重试复用已校验的 OCR 材料。
  读历史、审核、对照原卷不重新调用服务；普通结果仍待教师逐题核对后入库。
- 每题保存不可变的分角色表格结构基线，审核与发布都复查行、格位和合并结构；
  误删整表或一行可暂存为待审核，但不能确认发布，文字与数值核对后仍可更正。
  原题页图不能被模型移到答案字段后冒充已完整保留。
- 本机 TUN 的合成 DNS 对官方接口及本次核实的四个百度云下载域名作精确兼容；
  不扩大为任意内网或域名通配，不关闭 TLS、不跟随重定向，素材下载不携带识别密钥。

教师需在设置填写自己的 PaddleOCR Key；本次联调用凭据仅存在隔离回归目录的加密配置中。
PaddleOCR 识别可能有字符或归属错误，不能据本次两份结构验证将整批试卷自动放行。
