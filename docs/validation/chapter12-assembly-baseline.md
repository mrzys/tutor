# 第一、二章扩量前：真实组卷基线

测试日期：2026-10-12（香港时间）。测试入口为临时随机端口的 Nest HTTP 服务，使用独立 SQLite：`.tutor/chapter12-expansion/baseline-storage/tutor.sqlite`。未写入用户正在使用的 4319 数据库，未操作其账户或历史草稿。

## 判定

**集合基础巩固流程可用；含参提高目标及第一、二章完整覆盖尚未通过。** 可以继续用导入接口小批试运行、针对缺项扩题；不能以“全部题位有题”为标准宣称提高卷或整章卷质量合格。

这是真实当前配置 `deepseek-official / deepseek-flash` 的需求整理、蓝图规划、候选比较与保存结果，不是模型夹具。范围、完整解法边界和同卷去重仍由系统校验；三个环节均有真实模型调用记录及 token 使用量。

## HTTP 场景结果

| 教师请求 | 实际结果 | 机器端耗时 | 结论 |
| --- | --- | --- | --- |
| 10 道集合基础巩固，不计分，常规运用 | 8 单选 + 2 填空，10/10 选入，0 分，无重复题及重复组 | 17.067 秒：整理 0.905 秒，蓝图 3.838 秒，选题保存 12.285 秒 | 基础巩固可用；具体题目仍需教师浏览 |
| 6 道集合提高，含参关系、空集与非空分类、推理说明，不计分 | 5 单选 + 1 解答，6/6 选入，0 分，无重复题及重复组 | 19.551 秒：整理 1.763 秒，蓝图 6.255 秒，选题保存 11.478 秒 | 流程成功但目标覆盖不足 |
| 第一章混合：集合、充分必要条件、全称存在量词，10 题 | `POST /api/intake` start 返回 400，`invalid_intake` | 5 毫秒 | 当前组卷范围仅 1.1/1.2/1.3，1.4/1.5 未接入 |
| 第二章一元二次函数、方程和不等式，10 题 | start 同样返回 400，`invalid_intake` | 5 毫秒 | 第二章无法进入蓝图；不是显示留空，而是入口被拒绝 |

正常成功路径在界面对应一次需求输入、两次确认（采纳需求并规划、确认蓝图并选题）；HTTP 分成 start、prepare、adopt、confirm、plan、draft 六个请求。机器耗时不等于教师总工作量，本次未做人类用户计时；阅读、核题和修订时间未计入。

## 题面和目标复核

基础卷已阅读所有题干、选项及所选解法证据。题号为 `002、008、004、034、029、045、042、046、005、011`（共同前缀 `tutor-set-`）。集合确定性、归属关系、集合相等与包含、交并补均有题面活动；选择了 042 的平方约束区间并集，仍需教师判断是否符合其“基础”的班级尺度。本次没有独立难度标注，不能据“运算常规”就确认难度达标。

提高卷实际选择：

| 题目 | 活动 | 与要求的差距 |
| --- | --- | --- |
| tutor-set-036 | 空集是含参根集的真子集，转化为根集非空并求参数 | 有参数，但没有同时处理空集和非空两个分支 |
| tutor-set-047 | 并集、补集覆盖实数集，求参数 | 有参数与端点推理，没有空集分类 |
| tutor-set-050 | 补集交集、空交集条件与区间参数 | N 的区间长度恒为 2，因此 N 恒非空；交集为空不等于 N 可能为空 |
| tutor-set-035 | 两个固定有限集的真子集判断 | 无参数，是基础辨析 |
| tutor-set-037 | 有限集与区间交集的子集计数 | 无参数，是基础运用 |
| tutor-set-045 | 绝对值条件筛选有限集交集 | 无参数，是常规运算 |

所以 6 题中只有 3 题含参数，**没有一道真实包含空/非空两分支分类的题**。模型的候选说明已承认这些局限，但自动蓝图为填满题量仍纳入基础补充。当前教学目标是“尽量满足”，系统没有宣称已复核覆盖，`goal_support_unknown` 保留。该行为在合同上允许，不代表提高练习达到了教师意图。扩量应优先增加这类真正的分类题，随后重跑同一请求。

## 已发现的问题与小修

1. 首轮含参 quick_intake 的两次模型输出均触发业务校验，返回 HTTP 200、`session.assistantError=invalid_model_output`。基础条件保留，未采纳错误目标。之后独立正式重跑成功，说明失败不是持续服务不可用。最初记录只包含通用业务错误，未保存原始建议，不能断言其具体违规字段。
2. 针对可复现的“把锁定数值以相同值重复输出”模式，已加强 prompt：changes 必须在 supportedFields 中，锁定键连同值也须省略；校验反馈明确列出禁止键及允许键。不放宽校验，也不静默删除模型字段。新增回归模拟首轮 questionCount/scoringMode 同值被拒绝、二轮修正目标后成功且仍需教师采纳。quick-intake + llm 两个测试文件 24/24 通过。
3. 蓝图模型 summary 中的题型数量与结构存在不一致。基础摘要说“2 道解答调整为 2 道填空”，实际是 8/2/0；提高摘要说 4/1/1，实际是 5/0/1。现已改为服务端从最终校验通过的 slots/counts、计分模式、分值与时长构建教师可读摘要，原模型叙述仅保存为 modelSummary 供审计，逐题理由保留。新增回归用错误的“九道解答、999分”叙述证明展示结果仍以 1 单选 + 1 填空、不计分、20 分钟为准。
4. 当前整个组卷目录仅有集合 1.1/1.2/1.3；题库完整教材树不等于组卷任务和解法路径已经覆盖第一、二章。批量导入后须复测需求目录、任务与来源是否进入组卷查询。
5. 本次所有正式草稿 `difficultyEstimate=null`，并带 `difficulty_unknown`。当前 LLM 会在说明中描述简单、偏难等，但没有可供筛选和核验的正式难度结果。本次扩量必须写入有依据、明确为模型估计的难度字段，不能将认知要求当难度，也不能伪装为学生实测难度。
6. 第三轮真实重跑还暴露候选比较的不稳定性：基础卷第二批引用了无效 evidenceRefs，模型纠错后仍失败，HTTP 400，草稿未保存。已把原通用校验消息加强为具体题位、题目、违规键和该题允许的精确键，并明确必须有有效 student 题面键；严格身份、版本、引用校验不放宽。新增针对性回归。quick-intake、llm、selection、blueprint-planner 四个文件合计 44/44 通过。一次流程成功不能被解读为模型长期稳定率已测定。

## 小修后实际重跑

最终扩量前重跑（`baseline-http-after-quality-fixes.json`）中，基础卷 10/10、8 单选 + 2 填空，18.760 秒；提高卷 6/6、4 单选 + 2 解答，10.518 秒。两份均无同卷重复、不计分，教师可读摘要与实际题型配比一致。提高场景 quick_intake 首轮真实输出了禁止键 `response: written_reasoning`，精确反馈明确指出 response 后，第二轮删除该键而保留可观察目标，成功通过；这是实际模型纠错证据，不是测试夹具。初次失败的具体键仍不可从旧记录推定。

该轮提高卷改选了 041 根集合多问分类题，含参题增加至 4/6，但其根集恒含 x=1，不包含空集与非空两个分支；其余 035、045 仍为无参基础题。**因此修复提升了流程成功及说明准确性，未解决供给不足和目标错配。** 第一章完整和第二章请求仍返回 400，不把它们计作成功组卷。
