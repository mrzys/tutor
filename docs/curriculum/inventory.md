旧项目代码 `apps/api/src/paper-workflows-v2/question-semantic-v2.ts` 定义：认知“记忆/理解/应用/综合/探究”、四能过程、10 类内部能力指标、六大数学核心素养、高考四翼。`docs/teaching-training-assessment-objectives-and-content-structure.md` 明确区分官方框架与内部操作性能力分类。

这套认知枚举与知识树的“了解/理解/掌握”不是相同字段，也没有证据支持一一等同。题目认知要求、能力活动与核心素养须绑定题目/解法证据；教材知识映射不自动赋予题目这些维度。旧 `assembly-competencies.ts` 部分使用“考查能力”文案指六大素养，迁移时应保留字段语义并更正文案，不能把能力与素养合并。

## 完整映射结构与验收

1. `sourceDocument`：PDF hash、页数、原文件名；`edition`：出版社、系列、册别、版次年、ISBN、课标版本及版权页证据。不能仅按同名书合并。
2. `textbookNode`：版本内稳定 ID、父节点、章/节类型、顺序、印刷页/PDF 页区间、标题目录证据与提取/核验状态。分组本身不替代知识 UID。
3. `knowledgePoint`：保留旧 UID、名称、定义、父 UID；保存迁移快照版本和原始元数据，不静默改写或重新编号。
4. `coverageMapping`：教材 node/block → KP UID 的多对多关系，保存 introduced/explained/practiced/extended 等语义、主要/背景角色、来源页、原文引用、bbox/稳定块 ID、依据 hash、生成来源、核验状态及陈旧状态。旧 covered 先保留原词，转换须显式。
5. `legacyCrosswalk`：旧 public 节点/映射 ID、V2 revision/node/block ID、当前 edition/node/KP ID、匹配依据及状态；别名、同 UID 名称冲突单列。
6. `teachingDemand`：认知要求、内部能力、核心素养独立版本化关联，须引用教材原文或题目活动；不嵌入知识树当子节点，不把 mastery_requirement 当学生状态。
7. `coverageAudit`：按册逐条列出全部 423 个叶节点与全部章/节节点，分别统计已映射、候选待核验、多义冲突、无对应、版本不明、原文缺失。完整意味着全量有处置记录，不要求强行制造一个对应。

从旧 metadata 的册名/页码可自动生成定位候选；从已存在 63 条 public 与 526 条 V2 关系可迁移明确候选。仅凭页码落在某节不能推出“该节主要讲解此知识点”，正文证据及角色仍需确认。分组节点的集合归属可从叶映射向上聚合，但要标注 derived，不把聚合伪装成直接原文覆盖。

## 复核方式

`node docs/curriculum/collect-inventory.mjs` 从旧知识库配置读取连接串，在 `repeatable read read only` 事务中记录查询；仅导出教材/知识元数据与内容证据，不写旧数据库、不导出配置、对象 URI 或私有签名。`inventory.json` 内保留实际 SQL 与结果便于复核。

`local-sources.json` 的文件检查为 PyMuPDF 页数/前 12 页文本层与 SHA-256，不等于全文 OCR 完成、版权页/目录已视觉核验或数学公式已验收。
